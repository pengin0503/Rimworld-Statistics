## Common acceptance contract for Tasks 26–34

1. **Qualified measurement:** capture an observable committed transition, unit and owning player colony. Show exact 1.7 PackageId, active assembly, method/call site and success predicate. Count by qualified `<PackageId>/<DefName>` when a resource, ammo, animal, weapon, drone or outcome Def is meaningfully attributable; preserve scalar totals even if a breakdown is partial. Name the unit explicitly: `rounds`, `items`, `pipe units`, `silver`, `orders`, `people` or `events` as applicable. Do not treat an unrelated owner's identical DefName as the same key.
2. **Aggregation:** use the Experimental/Unverified, checkpoint-based lifetime family pipeline with eligible capture enabled by default for new installations and explicit opt-outs preserved and EN/JA translations. Independent colonies sum where additive; an all-time highest expertise level uses a **max** observation across independent colonies and representative checkpoint branches, *not* a sum. No latest-state-only single-save display is introduced. Keep prior records after uninstall and mark missing/unobservable windows partial.
3. **Distinctness:** verify each candidate against generic quest, crafting, mining, combat, social, work, skill, population and trade metrics before registering a new descriptor. If the same fact is already covered, implement the requested view via an existing qualified breakdown when possible and document why a duplicate MOD-specific counter is not added. This is a deduplication outcome, **not cancellation of the requested feature**.
4. **Safety and speed:** bind optional targets once during startup, fail closed on unexpected signatures, and never add polling/reflection, per-tick scanning or unbounded event allocations on the hot path. Honor `ProgramState.Playing`, inactive Scribe mode, ownership and DLC checks. Restore patch scopes even on exceptions. Only actual successful changes are recorded; failed, aborted, repeated, debug and load-time operations add zero.
5. **Tests:** each task needs positive, negative, partial-success, repeated-operation, and ownership cases. Include checkpoint/save/reload, same-colony rewind branch, independent second colony, MOD removal/reinstall, missing/changed assembly and 1.7 test host checks where available. Confirm unique metric IDs before registration, build and package correctness, and report runtime evidence separately from static source/IL.
6. **Delivery:** implement each task as a separately reviewable slice in the **Rimworld-Statistics host**. Close the task only when all distinct requested outcomes are implemented/tested, or when a specific outcome is demonstrably already represented by the current generic family with no loss of the requested breakdown or aggregation. If a concrete external input is required, leave the incomplete outcome tracked with that specific prerequisite. PR #209 makes no executable changes.

## Task-specific acceptance cases

- **26 · CE:** verify actual positive ammo debit for player weapons and count the exact number of rounds used, not number of shots or reload actions. Include magazine-fed and direct-use paths in the caller audit; a dry fire, disabled ammo mode, turret-only action or a reload moving existing ammo without consuming it from the game's intended accounting must not be mislabeled. For suppression, record a confirmed newly applied/threshold-crossing effect according to the source's semantics; repeated ticks of the same effect add zero. Before any metric ID is assigned, test the meaning of one suppression occurrence and bound hot-path cost.
- **27 · Gastronomy:** partial payments of 4 then 6 for a debt of 10 yield **one** fully settled order; two independent paid orders yield **two**. An unpaid/void/free order, debt write-off, canceled order, failed transfer and reloaded settled order add zero. The separate silver-collected metric remains +10 on the successful payment path.
- **28 · Prison:** parole-approved-but-still-present yields zero **departures**; actual release/departure yields one. The sentence-completion counter requires completion of the imposed sentence, not sentence reset as part of parole or save load. A riot starts without an outcome, fails, or is interrupted without a definitive end => no falsely claimed successful resolution; define result classes after source/IL inspection.
- **29 · Rimefeller:** confirm positive measured input/output deltas at a commit site, including fractional pipe quantities when supported. A timer, `Produced(int)` state alone, advertised capacity, crude present in a tank or a refinery bill attempt is not a counted produced/consumed unit. Record separate quantities for each real resource/type; bound thread ownership and race behavior before registering hooks.
- **30 · Pirates:** a completed real hire +1 and paid silver +actual positive amount; dialog view or canceled contract +0. Refunds, renewals, extensions and contracts created through alternative mechanisms require explicitly documented accounting rules; do not silently count them twice.
- **31 · Skills:** a newly earned expertise level is one progression event; repeated UI redraw, expertise re-selection, loaded level or temporary boost +0. For a peak record, compare an attained higher level with prior historical maximum and only raise the maximum on a genuine persistent change; avoid a fake sum of maxima.
- **32 · Security:** choose an outcome definition validated by upstream behavior, with one confirmed artillery mission/event adding one and its queued targeting or failed firing adding zero. Report breakdown by artillery or ammunition Def only when that attribution is stable. Distinguish the off-map artillery metric from generic explosions/kills.
- **33 · Genetics:** successful spawned hybrid +1 by resulting pawn kind; successful irreversible transformation +1 by resulting gene/creature Def if evidenced. Invalid target, aborted procedure, spawned-existing pawn, reloading and duplicate observer +0.
- **34 · Drone Factory:** hatch produces a live spawned player drone +1; destroyed egg without spawned pawn, blocked spawn, failed incubation and automated assembler production +0. Separate hatcher and assembler counters must not fire from the same spawn.
