# Popularity-first MOD-specific statistics prioritization — 2026-11-12

**Status:** read-only research and execution queue. **No C# implementation or Workshop update.** The [35-target master register](README.md) is the implementation-plan candidate list. This file supplies **relative execution priority across both old and new candidates**, overriding the old ad hoc `High / Medium` labels for **work sequencing**, but not deleting or declining any approved candidate.

## Method and uncertainty

1. **Reach first:** current Steam Workshop *Current Subscribers* is the initial sort key. These are **rounded approximate counts** from web-indexed pages observed during the 2026-11-12 investigation; the crawls have different timestamps (from days to months old). They **are not a unified, live Steam API snapshot**, and are not counts of players with Rimworld-Statistics installed.
2. **Then utility:** require a non-duplicate, player-meaningful, confirmed gameplay result distinct from existing vanilla and generic-def collectors. A million-subscriber cosmetic or generic recipe pack still should not get its own collector.
3. **Then evidence and cost:** 1.7 effective load path / selected DLL, recognizable completed outcome, success-based hook, low hot-path cost, optional dependency and no DLC assumptions. An absent 1.7 directory is not alone disqualifying when `loadFolders.xml` selects 1.6.
4. **Scoring policy:** priority bands are **P0 reach (~500k+), P1 (~250k–499k), P2 (~100k–249k), hold (unverified 1.7 or no distinct signal)**. Bands describe review order, **not unconditional implementation authorization**. Within bands order by subscribers; missing or stale counts should be verified before scheduling work. If the necessary unique event fails source/IL audit, record "blocked / generic only" rather than implementing a duplicate. Low-subscriber candidates remain in the master plan but come after higher-reach eligible work.
5. **Already supported targets:** do not treat a popular mod as an unimplemented feature if current main already captures its desired event. Audit the **current** host README and C# metrics and reuse the existing collection family. Do not add another provider for a metric that is already collected.

[Steam](https://steamcommunity.com/sharedfiles/filedetails/?id=2329011599).
- **More Faction Interaction (Continued) (~210k):** separate unique settlement/diplomatic events may be valuable, but no validated 1.7 active binary from this pass; 1.6-tagged Workshop evidence is insufficient. Hold for target identification/1.7 loader verification. [Steam](https://steamcommunity.com/sharedfiles/filedetails/?id=2379076640).
- **SRTS Expanded (~100k):** framework's shipped 1.7 compatibility must be proven for the correct active continuation. If verified, the existing research identifies **unique transport completions** distinct from Vehicle Framework; revisit after the higher-reach queue. [Steam](https://steamcommunity.com/sharedfiles/filedetails/?id=1845423808).
- General content packs adding only `ThingDef`, `PlantDef`, recipes, or generic incident-defs are **not** counted as new statistics families merely for popularity.
