# 手動確認の手順書（仕様 §11.2）

利用者の PC で、実際のゲームを使って確かめる項目です。この環境（ゲームを起動できない）で確かめた範囲は、末尾の「自動確認の記録」にまとめました。

- 対象: RimWorld 1.7（監査済み索引は 1.7.4985 rev1269）、前提 MOD は Harmony だけ
- 記録ファイル: `<SaveData>/RimworldStatistics/profile.json`（バックアップは `profile.json.bak1`〜`bak3`）
  - `<SaveData>` は `GenFilePaths.SaveDataFolderPath`（`Saves` フォルダの親）。実際のパスは統計ウィンドウの「取り込み状況」タブに出る
- 確認の前に、`Saves` フォルダと（あれば）`RimworldStatistics` フォルダを別の場所にコピーしておく

## 0. 準備

- [ ] 配布物を作る: `tools/fetch_dev_inputs.py refs .refs` のあと `bash tools/package.sh artifacts/RimworldStatistics.zip`。zip を展開した `RimworldStatistics` フォルダを `Mods` フォルダに置く（または Workshop の外の任意の MOD フォルダ）
- [ ] MOD 一覧で Harmony の後に「Rimworld Statistics」を有効にする
- [ ] MOD 設定に「通算統計（Rimworld Statistics）」があり、次の 2 つがある
  - 「開発モード中に記録したエンディングを表示し、合計に含める」— 既定はオフ
  - 「タイトル画面で自動的にセーブを取り込む」— 既定はオン

## 1. 起動とボタン（RimSaves と一緒に）

- [ ] 起動して、`Player.log` に `[RimworldStatistics]` のエラーが無い
  - `Could not apply …` が出たら、そのパッチ名を控える（そのパッチの機能だけが止まり、他は動く）
- [ ] `Player.log` の先頭付近の版（`RimWorld 1.7.xxxx rev…`）を控える: ________
  - 1.7.4985 と違う版なら、その版の DLL で `tools/refcheck.sh` と `tools/check_patches.sh` をやり直す（仕様 §14）
- [ ] タイトル画面で、「オプション」の直前に「通算統計」ボタンがある
- [ ] RimSaves を有効にした状態でも、ボタンと RimSaves のセーブ一覧が両方動く
- [ ] 右側の Web リンクの列にはボタンが増えていない

## 2. 取り込みと合計（受け入れ条件 2、3、9）

- [ ] タイトル画面を表示すると取り込みが始まり、「取り込み状況」タブで進捗バーと件数が動く
- [ ] 取り込み時間を測る: ______ 秒（目安 60 秒以内。この環境の C# 版では 49 件で 3.3〜3.7 秒）
- [ ] R2 の 49 件と同じセーブなら、「概要」タブが次の値になる

| 項目 | 期待値 |
|---|---|
| コロニー数 | 33 |
| 通算ゲーム内日数 | 2,262.1日（37年42日）＝ 135,723,149 ティック |
| 実プレイ時間 | 263.9時間（950,114 秒） |
| エンディング到達回数 | 0 |
| 旅立った人数 | 0 |
| 最高資産の合計 | 4,364,583 |
| 敵の襲撃 | 190 |
| 大きな脅威 | 311 |
| 入植者の死亡 | 29 |
| 最長存続 | 347.3日（5年47日）＝ 20,835,213 ティック |
| 単一コロニーの最高資産 | 925,790 |
| 最大人口 | 20 |
| 最終資産の合計 | 4,294,287 |

- [ ] セーブが 49 件から増減していれば、差をコロニー単位で説明できる（「コロニー」タブの行を選ぶと、元になったセーブが出る）
- [ ] 「再スキャン」をもう一度押すと、「読んだ 0 件／読み飛ばした N 件」になり、数値が変わらない
- [ ] 各数値のツールチップに「N コロニー分から計算（合計から外したもの M）」が出る。エンディングと旅立った人数のツールチップに、MOD 導入前は痕跡だけで数える旨の説明が出る
- [ ] 取り込み前後で、`Saves` のファイルの更新日時が変わっていない（セーブには書き込まない）
- [ ] 取り込み中に「中止」を押すと止まり、統計ウィンドウを閉じても再開しない（「再スキャン」で再開する）
- [ ] この MOD を更新した後の最初の取り込みでは、全ファイルを読み直す（読み取りの版が上がったため）。読み直しの後も数値が変わらない

## 3. 新しいゲーム（受け入れ条件 1）

- [ ] 新しいゲームを始めると、取り込みが中断される（タイトル画面に戻ると続きから読む）
- [ ] ゲーム内で半日以上進めてセーブし、タイトル画面へ戻る
- [ ] 「コロニー」タブでコロニーが 1 つ増え、日数と資産が入っている。行を選ぶと「（プレイ中の記録）」が出る
- [ ] `profile.json` の `liveCampaigns` に項目が 1 つ増えている
- [ ] 新しいゲームを始めて、セーブせずにタイトル画面へ戻る（マップの選び直しなど）。コロニー数が増えない

## 4. MOD 導入前のセーブ（受け入れ条件 5）

- [ ] MOD 導入前に作ったセーブ（1.5〜1.7）をロードし、別名でセーブしてタイトル画面へ戻る
- [ ] 「概要」のコロニー数が増えていない。元のコロニーの行に、新しいセーブと「（プレイ中の記録）」がまとまっている
- [ ] 同じコロニーの導入前セーブをもう一度ロードしてセーブしても、コロニー数が増えない
- [ ] MOD 設定で「タイトル画面で自動的にセーブを取り込む」を**オフ**にしてゲームを再起動し、統計ウィンドウを開かずに導入前セーブをロードしてセーブする。`Player.log` に `[RimworldStatistics]` のエラーが出ず、タイトル画面へ戻ると既存のコロニーにまとまっている（ロード処理はゲームの裏スレッドで動く）
- [ ] （調査 §8 の未確認事項）ロード中に読む資産の先頭値と、セーブの値が一致している（一致しないとコロニーが増える）

## 5. エンディング（受け入れ条件 6、7）

### 宇宙船（開発モードの「Force start ship」）

準備:
- [ ] オプションで開発モードをオンにする。上部の開発ツールで「God mode」をオンにする（建築が一瞬で終わる）
- [ ] 必要なら開発メニューで研究を完了させ、建築メニューの「宇宙船」から次の 2 つを置く
  - 宇宙船コンピューターコア（`Ship_ComputerCore`）
  - 宇宙船用冷凍睡眠棺（`Ship_CryptosleepCasket`）。普通の冷凍睡眠棺ではない
  - 棺はコアと**辺で接する**ように置く（斜めは不可。間に宇宙船の部品を挟んでもよい）。1.7.4985 の `ShipUtility.ShipBuildingsAttachedTo` は、上下左右に隣り合う宇宙船部品だけをたどる
- [ ] 入植者を 1 人、棺に入れる
- [ ] ここで別名でセーブする（例: `before-ship`）

確認:
- [ ] 開発メニュー「General」の「Force start ship」を実行する。約 7 秒後にクレジットが出る
- [ ] タイトル画面へ戻り、MOD 設定の開発モードの設定が**オフ**のとき
  - 「エンディング」タブに出ない。「概要」のエンディング到達回数は 0、旅立った人数は 0
- [ ] 設定を**オン**にすると
  - 「エンディング」タブに「宇宙船・1 回目・1 人・プレイ中の記録（開発モード）」が出る。到達回数 1、旅立った人数 1
- [ ] `profile.json` の `endingEvents` に `"type": "ship"`, `"ordinal": 0`, `"devMode": true`, `"departed": 1` がある
- [ ] `before-ship` をロードしてもう一度打ち上げると、回数が増えない（同じ 1 回目として扱う）
- [ ] 打ち上げの後のゲームで、同じ手順をもう一度行う（2 隻目）と、2 回目として増える
- [ ] 開発メニュー「Force ship countdown」（船なし）では、「宇宙船・旅立ち 0 人」として記録される

### 他のエンディング（開発ツールで再現できる範囲）

- [ ] 王族の昇天: 入植者がシャトルで旅立った時点で「王族の昇天」として記録され、その後のクレジットで二重に記録されない
- [ ] アーコネクサス: クレジットの後にタイトル画面へ戻っても、「アーコネクサス」として記録されている
- [ ] セレブレックス・コア: 回収と破壊が、それぞれの種類で記録される
- [ ] どのパッチも効かなかった場合でも、クレジットは「その他」として記録される（仕様 §14。Waylith 上で小さな非公開メソッドへの Harmony が効くかは未確認）

## 6. 性能（受け入れ条件 11）

Dubs Performance Analyzer で確かめる。
- [ ] Tick の項目に `RimworldStatistics` のメソッドが出ない（毎ティックの処理はゼロ）
- [ ] セーブ 1 回あたり、`GameComponent_RimworldStatistics.ExposeData` の追加時間が 50ms 未満
- [ ] タイトル画面で、統計ウィンドウを開いても 100ms 以上止まるフレームが出ない

## 7. MOD を外す

- [ ] MOD を外してから、MOD 付きで作ったセーブをロードできる（`GameComponent_RimworldStatistics` が見つからない旨のログは出てよい）

## 8. 記録ファイルの異常（受け入れ条件 12）

- [ ] ゲームを終了し、`profile.json` の中身を途中で切って保存する。起動すると、`bak1` から復旧した旨の警告が `Player.log` に出て、壊れたファイルは `profile.json.corrupt-<日時>` として残る。「取り込み状況」タブの読み込み元が「バックアップ 1」になる
