# RimWorld 1.7 実現可能性調査（通算統計MOD）

- 調査日: 2026-11-06
- 対象: RimWorld **1.7.4985 rev1269**（Core / Royalty / Ideology / Biotech / Odyssey）
- 方法: 静的解析のみ。ゲームの起動、セーブの保存・読込の往復、Harmony の適用、実 TPS の測定は行っていない。
- 本書は [設計仕様 v0.2](../superpowers/specs/2026-11-06-rimworld-statistics-design.md) の根拠資料である。

## 1. 根拠と検証方法

| 根拠 | 内容 | 検証 |
|---|---|---|
| 監査済み索引 | R2 `rimworld-17/research/vanilla-1.7.4985-audited/`（型・メソッド・呼び出し関係・Def） | `index.json` の SHA-256 と 240 ファイルが一致 |
| ゲーム DLL | `Assembly-CSharp.dll`, `UnityStubs.dll`, `RimWorld.dll`, `Waylith.dll`, `Waylith.UnityCompat.dll` | 監査済み `source-provenance` の SHA-256 と一致 |

## 2. 実行環境とビルド規約

- ゲームは `net10.0`（WaylithCLR `10.0.13-waylithclr.dev`）で動く。`UnityEngine*` の参照は `UnityStubs` へ転送される（`RimWorld.runtimeconfig.json`）。
- `WaylithClr.JitPatchableAssemblies = Assembly-CSharp`。Harmony で差し込めるのは、少なくとも設定上は Assembly-CSharp。
- 利用者の既存 1.7 用 MOD の csproj は `TargetFramework=net10.0`。参照は `Assembly-CSharp`、`UnityStubs`、`Waylith`、`0Harmony`。参照先の場所は `$(GameDir)` と `$(HarmonyDll)` で与える。
- Harmony は Manifest 3.0.1.0 で、`1.7/Assemblies/0Harmony.dll` がある。
- `System.Text.Json.dll` はゲームに同梱されている（`Game-Linux/`）。
- バニラのセーブ一覧画面（`Dialog_SaveFileList`）は、`Task.Run` でセーブ情報を裏で読み込む。

## 3. セーブ形式

- 形式は XML。`GameDataSaveLoader.SaveGame` → `SafeSaver.Save(path, "savegame", …)` の順に呼ばれ、`<savegame><meta>…</meta><game>…</game></savegame>` になる。
- `meta`: `gameVersion`、`modIds`、`modSteamIds`、`modNames`（`ScribeMetaHeaderUtility.WriteMetaHeader`）。
- `Game.ExposeData` での保存順は次のとおり（抜粋）。統計に使う要素は、巨大な `world` と `maps` より後ろにある。
  `… world, maps, info, rules, scenario, tickManager, playSettings, storyWatcher, gameEnder, … storyteller, history, taleManager, … uniqueIDsManager, questManager, … components`
- `Scribe_Values.Look` は、値が既定値と等しいとき要素を書かない。欠けている要素は既定値として扱う必要がある。
- 保存先は `GenFilePaths.SavedGamesFolderPath`（= SaveData/`Saves`）。`GenFilePaths.AllSavedGameFiles` は直下の `.rws` だけを列挙する。

### 3.1 統計に使う要素（ラベルは逆コンパイルで確認）

| XML パス（`savegame/game/` 以下） | 型・既定値 | 意味 |
|---|---|---|
| `info/realPlayTimeInteracting` | float 秒、既定 0 | 実際に操作していた時間 |
| `info/permadeathMode` | bool、既定 false | パーマデス |
| `info/permadeathModeUniqueName` | string | パーマデスのセーブ名（勢力の命名で変わる。§6） |
| `info/startingTile` | 1.5: `"221529"` / 1.6 以降: `"221529,0"` | 開始タイル |
| `info/startingAndOptionalPawns/li` | 参照 ID（例 `Thing_Human123`） | 初期入植者。読み込み後に null が除かれ、減る一方 |
| `tickManager/ticksGame` | int、既定 0、1 日 = 60000 | 経過ティック |
| `tickManager/gameStartAbsTick` | int、既定 0 | 開始時刻 |
| `tickManager/startingYear` | int | 開始年 |
| `world/info/seedString` | string | シード文字列 |
| `world/info/persistentRandomValue` | int、既定 0 | ワールドの乱数値（§6） |
| `world/info/name` | string | ワールド名 |
| `world/factionManager/allFactions/li` | `def`、`name`、`deactivated` | プレイヤー勢力名、機械族の停止フラグ |
| `scenario/name` | string | シナリオ名 |
| `storyteller/def`、`storyteller/difficulty` | Def 名 | ストーリーテラーと難易度 |
| `storyWatcher/statsRecord/numRaidsEnemy` | int、既定 0 | 敵の襲撃回数 |
| `storyWatcher/statsRecord/numThreatsQueued` | int、既定 0 | 大きな脅威の数（フィールド名は `numThreatBigs`） |
| `storyWatcher/statsRecord/colonistsKilled` | int、既定 0 | 入植者の死亡数 |
| `storyWatcher/statsRecord/colonistsLaunched` | int、既定 0 | エンディングで旅立った人数 |
| `storyWatcher/statsRecord/greatestPopulation` | int、**既定 3** | 最大人口 |
| `history/autoRecorderGroups/li/recorders/li/{def, records \| recordsDeflate}` | Base64 の float32 配列（LE）。`recordsDeflate` は生の deflate（Ionic.Zlib） | 履歴グラフの記録 |
| `questManager/quests/li/{root, ended, endOutcome}` | Def 名、bool、列挙値 | クエストの結果。終わったクエストも消えずに残る |
| `components/li[@Class]` | クラス名 | GameComponent。Anomaly は `levelDef` |

- 履歴記録 `Wealth_Total` / `Wealth_Items` / `Wealth_Buildings` / `Wealth_Pawns` / `FreeColonists` などは 30000 ティック（半日）ごとに記録される。
- `HistoryAutoRecorder.records` から要素を消す処理は無い（ロード時の Clear だけ）。そのため、最新のセーブに開始以来の全系列が入っている。
- `Wealth_Total` は、全プレイヤーホームマップの `wealthWatcher.WealthTotal` の合計である。
- `HistoryEventsManager` は時間の経過で整理されるので、累計には使えない。
- `TaleDef LaunchedShip` は `Volatile`（時間で消える）。手紙の保管（Archive）は固定されていない分が 200 件まで。

### 3.2 カウンタを増やす箇所

| カウンタ | 増やす箇所 |
|---|---|
| `numRaidsEnemy` | `IncidentWorker_RaidEnemy` |

## 4. エンディング

`GameVictoryUtility.ShowCredits(string, SongDef, bool exitToMainMenu = false, float songStartDelay = 5f)` を呼ぶ箇所は、次の 8 か所ですべてである。

| 呼び出し元 | DLC | エンディング | タイトル画面へ戻るか |
|---|---|---|---|
| `ShipCountdown.CountdownEnded`（`shipRoot` あり） | Core | 宇宙船。旅の申し出の脱出船も同じ処理を通る（`SymbolResolver_Ship_Pregen` が `Ship_ComputerCore` を置き、`TryLaunch` → `ForceLaunch` → `InitiateCountdown(Building)` と進む） | 戻らない |
| `ShipCountdown.CountdownEnded`（`customLaunchString` あり） | Royalty | 王族の昇天。`QuestPart_EndGame` が `InitiateCountdown(string)` を呼ぶ | 戻らない |
| `ShipCountdown.CountdownEnded`（どちらも無し） | — | デバッグ操作 `ForceShipCountdown` だけが通る | 戻らない |
| `ArchonexusCountdown.EndGame` | Ideology | アーコネクサス | **戻る** |
| `CompCerebrexCore.DeactivateCore(bool scavenging)`（2 か所） | Odyssey | セレブレックス・コアの回収／破壊 | 戻らない |
| `VoidAwakeningUtility.EmbraceTheVoid(Pawn)` / `DisruptTheLink(Pawn)` | Anomaly | 虚無を受け入れる／断ち切る | 戻らない（既定値） |

- Biotech 固有のエンディングは無い。利用者の環境（R2 のゲーム）には Anomaly のデータが無い。
- 王族の昇天（`EndGame_RoyalAscent`）のクエストは、要人を乗せたシャトルが出発すると `Success` で終わる（`pickupShipThing.SentSatisfied`）。エンディングは、入植者も同行した場合（`SentWithExtraColonists`）だけ起きる。**クエストの成功だけではエンディングの証拠にならない。**
- メカハイブ（`Gravcore_Mechhive`）のクエストは、`CoreDefeated` で `Success` になる（`QuestNode_Root_Gravcore_Mechhive`）。`Faction.OfMechanoids.deactivated = true` は**破壊したときだけ**設定される。
- Anomaly は `GameComponent_Anomaly.levelDef` が `Embraced` または `Disrupted` になる。
- アーコネクサスはタイトル画面へ戻るので、その後のセーブは存在しない。

### 4.1 開発モードの操作

- `DebugActionsMisc.ForceShipCountdown`: `InitiateCountdown((Building)null)`。船なしで終わる。
- `DebugActionsMisc.ForceStartShip`: 現在のマップにある `Ship_ComputerCore` から `ForceLaunch` する。

## 6. 同じコロニーの識別

- バニラには、セーブをまたいで使える一意の ID が無い。`ExternalHistory`（`.rwh`）の `gameplayID` は、読み込む側の処理だけが残っていて、書き込む処理が無い。
- `WorldInfo.persistentRandomValue` は、`WorldGenerator.GenerateWorld` で `Rand.Seed = GetSeedFromSeedString(seedString)` を設定した後、フィールドの初期化で決まる。**同じシード文字列なら同じ値になり得る。**
- パーマデスでは、勢力に名前を付けたとき（`NamePlayerFactionDialogUtility.Named`）に `permadeathModeUniqueName` が変わる。このとき自動セーブが走り、古い `.rws` は削除される。**この名前で別コロニーと判定してはいけない。**
- 利用者のセーブ 49 件で、次の判定キーを検証した。
  - キー: `seedString` + `persistentRandomValue` + `startingTile`（層番号を補った形）+ `gameStartAbsTick` + `Wealth_Total` 系列の先頭値。
  - 条件: そのうえで、`startingAndOptionalPawns` の ID 集合が包含関係にあること。
  - 結果: **49 ファイルが 33 コロニーにまとまった。** 手作業で確かめた範囲で、誤ってまとめた例・誤って分けた例は無い。
  - 例 A: パーマデスで命名した前後のセーブ（`.rws.old` が残った古い名前と新しい名前）は 1 つにまとまる。
  - 例 B: 同じシード・同じタイル・同じ開始時刻で、初期入植者と開始時資産が違うプレイは分かれる。
  - 例 C: 名前の違うセーブ同士（序盤のセーブと後のセーブ）は 1 つにまとまる。
  - 例 D: 初期入植者が死亡して減った後のセーブも、包含関係により同じコロニーとしてまとまる。
- プレイヤー勢力名は未命名のこともある。名前が同じ別コロニーもある（同名 6 件）。勢力名は表示にだけ使う。

- 利用者のゲームは 1.7.4985 より新しい版である。§5 の形が変わっていないか。
