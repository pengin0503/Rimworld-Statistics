# 過去セーブの実験的統計・復元可能性の一次調査（2026-11-09）

ソース基準：`main` v1.2.2 `be846980`。全264行は [CSV](2026-11-09-historical-recovery-inventory.csv) に保存した。コード上の分類のみであり、**復元成功の判定ではない**。今ある数値を一律に「過去から復元済み」とはしない。

## 正式な分類

| ソース取得方式 | 項目数 | 一次判定 | 追加の裏付け |
| --- | ---: | --- | --- |
| `LiveCatalog` (event family) | 214 | `EVENT_LOG_REQUIRED` | セーブ内の確定イベント記録または同じ意味の既知の累積カウンター。ほぼすべての個別日時は現在のSaveReaderで記録されていない |
| `SnapshotCatalog` (save time) | 41 | `SAVED_STATE_CANDIDATE` | 該当セーブ時点の本体・DLC・MODオブジェクトが正確にシリアライズされていることと、その値を解釈する対応Def・バージョン |
| `RankingDependencyCatalog` | 9 | `DEPENDS_ON_INPUT` | ランキングの元になるスナップショットかイベント系列の正確性 |
| 合計 | **264** | **すべてUNVERIFIED** | 自動判定は「開発可能性の入口」であり、真値の証明ではない |

## 41件の保存時点取得候補をさらに分類

| 単位 | 件数 | 既存のセーブから読み取る場合の課題 |
| --- | ---: | --- |
| `research_state` | 3 | `researchManager/progress`の値だけでは研究完了か分からず、当該セーブと一致する研究Def・完了条件が必要。研究完了日時までは復元できない |
| `factions` | 2 | 保存時点の勢力関係/友好度のXMLスキーマを監査。過去に消えた関係・最悪の値は単独のセーブでは分からない |
| `roster` | 12 | マップ・ワールド側のPawnを識別、所属や奴隷/メカノイドを区別。旧版やMODで保管場所・Pawn定義が変わる可能性がある |
| `facilities` | 10 | マップ中の建築物・電力系・屋内判定が必要な項目がある。大規模マップの解析によるCPU/メモリ負荷を測る |
| `stock` | 9 | 地上アイテム・インベントリ・品質等の状態を区別。重複保管やコンテナ、MOD定義との整合が必要 |
| `colony_start` | 1 | 開始タイルとワールドグリッドのバイオームを突き合わせる。現在の開始地点と同じとは限らない |
| `royalty_state` | 1 | Royaltyの保存情報から現存Pawnのサイリンクを識別。離脱したPawnの過去最大は保証不能 |
| `biotech_state` | 2 | 汚染状態・メカノイド帯域のゲーム/マップ側保存形式を確認。単一セーブから過去ピークは導けない |
| `royalty_quests` | 1 | 保存済みクエストに信頼できる帝国所属の識別子が必要。現行Readerは帰属根拠不足でこの値を復元しない |
| **合計** | **41** | |

上表の「候補」は**直接復元可能と確定した項目ではない**。`latest`はセーブ当時の状態、`peak`/`min`は複数の観測時点の最大/最小に過ぎず、ゲーム全期間の真のピークにはならないことがある。

## 既に実装済みの読み取りと、ここから増やすもの

**既に取得中（264項目とは別のPhase A）:** `storyWatcher/statsRecord` の襲撃・死亡カウンター、`history/autoRecorderGroups` の資産・人口・心情の7系列、`questManager` に残っているクエスト状態、その他v1統計。これを別の実験的な `Live` 項目にそのまま複写すると、定義や対象期間が異なるため二重計上・誤計上になる。

**次に実装する対象:** 原本を匿名化した1.7セーブと、実際に使ったMOD/DLCの保存仕様を検証し、1単位ずつ厳密な `SaveSnapshot` の項目として追加する。Readerのバージョン更新による初回再読み込み・失敗時データ保持・既存の保存値との共存を自動テストする。

**複数セーブの差分:** 同じコロニーIDは同一枝を保証しない。枝の証明なしの差分を確定イベントや全コロニー合計に加算しない。イベントの時刻は保存間の区間としてのみ示す。
