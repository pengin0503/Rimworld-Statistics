## 1. 目的・範囲

統計の値や取得仕様を変えず、利用者が「値を見つける／理解する／比較する／グラフを読む」までの操作数・視線移動・文章量を減らす。数値一覧を中心に据え、グラフはオンデマンドの補助表示のまま維持する。対象は通算統計ウィンドウの概要・詳細統計・取得状況・コロニー比較・ランキング・棒グラフ・履歴グラフ、および全12言語の表示文言。

### 不変条件

- 統計ID、集計・記録値、集計範囲、コロニーの除外、検索結果、順位の計算、記録品質、数値の丸め、欠測と実測0の区別を変更しない。
- Unknown／NotApplicable／Partial／Experimental を勝手に Complete／Verified または数値0へ変換しない。
- セーブの親子関係が証明されないグラフ点は接続しない。異種の履歴記録元は混ぜない。最新セーブが最終記録と同じ分岐に属すると断定しない。
- profile.json、チェックポイント、ModSettingsの保存形式、CSV、公開SDK、Harmonyパッチ、取得頻度、ゲームtick処理は変更しない。必要なUIローカル状態はメモリに置く。
- 実装言語は C#／.NET 10／RimWorld 1.7。ゲーム内 UI は Verse/Unity の既存ウィジェットを優先。12言語とも意味・プレースホルダーを揃える。
- R2 は既存参照コードの**読み取り専用**、GitHub ReleaseとSteam Workshopは更新しない。ゲーム内検証可能なら rimworld-for-mod-test を用い、不可なら未検証と明記する。
- これは表示上の改善計画であり、「内部実装上の注意」を隠すことと「統計の定義」を消すことを混同しない。

| 案 | 概要 | 判断 |

| **B 既存画面へ段階適用** | 共通部品を小規模に整え、文言→詳細→比較→グラフの順で改善 | **推奨**。現在の StatsTable、ColumnLayout、ControlRow、遅延表示・キャッシュを活用 |

### U02：派生統計の構造に関する追加規則

- **文字列の前方一致や同一数値**で基礎統計を判別しない。CrossColonyCatalog の定義、StoredKey、派生キーの関係を利用する。
- 対象の存在を消さない。「派生指標を表示」操作、または折りたたみ親行から合計／最大／最小を明示的に展開できる。
- 派生値が同一のコロニー1件ケースでも統計は3件とも保持。お気に入りのキー・グラフ遷移先は既存どおり。
- 全行並べ替え（値順・項目名順）や検索結果のとき、子行を隠してヒット件数と値の順序を誤認させない。初期案は「通常の名前順の全コロニー表示のみグループ化し、検索語があるとき／値順のときはフラット表示」。正確な実装条件は計画に準拠。
- 他カテゴリ・他MOD・SDK由来で意味を共有しない統計を誤って束ねない。ユーザーが強制展開を操作した場合は保持する。

### U04/U05：取得状況の情報階層

- 普段見る表には「分類名／統計／記録状態／対象数」を表示。取得失敗・DLC欠如・SDKのイベントID上限などの**行動可能な状態**は消さない。
- 取得単位ID・内部キー・Provenance の enum は一般表示から除外。診断情報が必要な場合は、開発者向け表示など別経路への退避を検討する（この設計では新しい診断画面を要求しない）。
- 翻訳できない外部SDKの分類は既存ラベルを使い、空文字・文字化け・衝突時に別グループが誤統合されないこと。内部IDは識別には引き続き使用する。
- 初期全展開は現状 Expanded.UnionWith(...) で行われる。既存の展開状態を毎回勝手に上書きしないこと。

### U11/U12：グラフ

- 棒グラフの目盛りは 1/2/5 × 10^n の読みやすい段階を候補とする。0基準の既存仕様と正負両方向を保つ。超大・極小・ゼロのみの系列でも NaN や無限大を描画しない。
- 履歴グラフは単一コロニー＋最大2件の比較コロニーという現行制約を維持。削除ボタンは対応 Overlay のみ取り除き、非表示になった線・系列色・範囲・凡例キャッシュを再計算する。進行中の読込結果で外した線が再出現しない。
- 横軸のセーブ時点、部分記録の色、白抜き点、欠測の目印、証明された祖先のみ結ぶルールは保持。色・点種・説明の対応関係を崩さない。

## 4. 文章改善候補（全12言語）

### 表示の基本規則

1. 表にすでに表示されている数値・状態をツールチップで言い直さない。初期表示はおおむね2〜4行を目安とするが、意味を損なう定義がある場合は行数制限より正確さを優先する。
2. 「欠測」「未記録」「0」「対象外」「記録期間だけの累積」「セーブ時点の値」の違いは削除しない。説明を削除しても状態列・母数は保持する。
3. 技術的な手段（内部メソッド、イベントID、Defの内部キー、再読込フック）は通常説明から外す。統計の数え方や「含む／含まない」は必要なら維持する。
4. 日本語原文→各言語へ意味を揃えて翻訳。全12言語のXMLキーと置換引数を一括検査。更新後、英独仏など長くなる言語の画面幅も検証。
5. 関連する別画面（CSV、記録状態、取得状況）で同じ翻訳キーを利用していないか、削除前にコード検索を行う。キー削除は参照0件を確認した場合のみ。

### 初回の置換候補（表現は意味検証後に確定）

### さらに確認する長文の対象

- 原文の長さだけで一括削除しない。現行日本語 Keyed に長文（90文字超）が数十件あるが、数え方の定義である場合が多い。
- Hospitality、Dubs Bad Hygiene、Rimefeller、Combat Extended などの統計説明は、「誰の／どのイベントを数えるか」「何を除外するか」「累積かスナップショットか」を保持し、実装メソッド名や重複回避の内部事情のみを整理。
- RWS_Status_Caution（取得状況の全体注意書き）は既存の他の品質表示との重複を見て短縮／折りたたみを検討。ただし SDK イベント容量超過の警告は削除しない。
- グラフの履歴系統説明 RWS_Chart_PointBranch / PointContinues / PointUnlinked / PointSavedLater は誤った系譜解釈を防ぐ意味がある。短縮しても事実の確度を上げない。
- 内容の変更と誤訳訂正は別タスクとして扱い、翻訳を原文の意味と一致させる。

## 5. 表示品質の共通基準

- 正常・部分・欠測・対象外は数値0とは独立に認識できる（色・短い言葉）。コントラストを損なわない。
- 行高・列幅・横スクロールの設計は現在の ColumnLayout / StatsTable / ControlRow を再利用し、大きいデータを毎フレーム全件レンダリングしない。
- タイトルや長いコロニー名、英語・ドイツ語・ロシア語など長い訳でも、切れたテキストを確認できる。ツールチップの二重登録は避ける。
- 例外・空データ・取得失敗時の画面が崩れず、操作先も明確。長いプロフィール操作でも UI 内に同期I/Oや新しいデータ集計を埋め込まない。
- 最低確認条件：0/1/35コロニー、実測0/負数/Partial/Unknown、内訳なし/多数、長い名称と12言語、ウィンドウ小/標準/拡大/画面に合わせる、画面解像度とUI倍率。
- 既存のコロニーグループ・除外・お気に入り・検索・比較・ランキング・CSV・セーブ分岐表示は回帰なし。
- GitHub Actionsにあるコンパイル、Core単体テスト、翻訳キー照合を必須。ゲーム画面での操作と多言語のレイアウト目視は自動テストと区別する。

## 7. 未検証・判断を要する点

- 本書は **実装内容の承認ではなく、候補を実装可能な設計として保存するもの**。実装時は最新 main の既存改善を確認し、既に実装されたものを重複して実装しない。
