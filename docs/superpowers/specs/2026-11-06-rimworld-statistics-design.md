# RimWorld Statistics — 設計仕様（v0.2）

- 作成日: 2026-11-06（v0.1 を同日に改訂）
- 状態: **レビュー待ち**。ゲーム用コードは未実装。
- MOD の対象: RimWorld **1.7**。MOD 自体は 1.7 用にだけ作る。
- 取り込むセーブ: **1.5〜1.7**。
- 利用者: 作者本人。本人の環境と MOD 構成で動けばよい。Workshop での公開は対象外。
- 前提 MOD: **Harmony だけ**。
- 根拠資料: [RimWorld 1.7 実現可能性調査](../../research/2026-11-06-rimworld-1.7-feasibility.md)（以下「調査」）。

## 1. 目的

タイトル画面から、どのセーブもロードせずに、これまでのすべてのプレイを通した通算記録を見られるようにする。

- MOD 導入前のセーブも、取れる範囲ですべて取り込む。最初の版から全部の統計を揃える必要はないが、できるだけ多く見られるようにする。
- セーブを消しても、取り込み済みの記録は残す。
- 同じコロニーのセーブが何個あっても、数字が水増しされないようにする。

## 2. 決定事項

| # | 論点 | 決定 |
|---|---|---|
| D1 | 何を記録するか | 「脱出」ではなく、**すべてのエンディング**を種類別に記録する |
| D2 | 同じエンディングを何度も見た場合 | **やり直しは数えない**。エンディング前のセーブで再達成しても増えない。同じ流れの中で新たに達成した場合（例：2 隻目の船）は数える |
| D3 | 「合計資産」の主指標 | **各コロニーの最高資産の合計**。最終資産の合計は副指標 |
| D4 | 利用者 | 本人専用 |
| D5 | 方式 | **案 1**：既存セーブの解析とプレイ中の記録を併用する |
| D6 | 開発モード中の記録 | 常に記録する。表示し合計に含めるかどうかは設定で切り替える（既定はオフ） |
| D7 | 前提 MOD | Harmony だけ |
| D8 | 対象の版 | MOD は 1.7。セーブは 1.5〜1.7 を読む |

## 3. 用語

| 用語 | 意味 |
|---|---|
| コロニー | 同じ開始状態から続く 1 回のプレイ。複数のセーブ、序盤のセーブ、分岐したセーブを含む |
| 観測 | ある時点のコロニーの値。セーブ 1 ファイルを読んだ結果か、プレイ中のセーブ時に読み取った値 |
| 流れ | 1 つのセーブが、開始から引き継いできた経緯。ロードしてやり直すと別の流れになる |
| 痕跡 | セーブ内に残った「そのエンディングに少なくとも 1 回到達した」証拠 |
| コロニー ID | MOD が付けて、セーブに書き込むランダムな固有値（GUID） |
| 判定キー | セーブ内の値から作る、コロニー識別用の組（§7.4） |

## 4. 統計の定義

各値は、合計から外したコロニーと、識別できなかった観測を除いて計算する。「最大」は、そのコロニーのすべての観測（セーブとプレイ中）の中での最大を指す。

### 4.1 最優先（概要タブの上段）

| 統計 | 定義 | 既存セーブから |
|---|---|---|
| 通算ゲーム内日数 | Σ コロニーの最大 `ticksGame` ÷ 60000。年でも併記する（60 日 = 1 年） | 取れる |
| エンディング到達回数 | Σ コロニー Σ 種類 max(そのコロニーのその種類の記録にある「何回目か」の種類数, 痕跡があれば 1)。種類ごとの内訳も出す（§4.3） | 痕跡だけ |
| 旅立った人数 | Σ コロニー max(最大 `colonistsLaunched`, 記録したエンディングの旅立ち人数の合計)。<br>最大 `colonistsLaunched` には、①② の観測に加え、③ の `launchedTotalAfter`（エンディング直後の累計値。§8.4）も含める。<br>旅立ち人数の合計は、種類と「何回目か」の組ごとに、記録の中の最大値を 1 つずつ足す | 取れる（エンディング後にセーブした場合） |
| 最高資産の合計 | Σ コロニーの最大 `Wealth_Total` | 取れる |
| コロニー数 | 合計に含めるコロニーの数 | 取れる |
| 実プレイ時間 | Σ コロニーの最大 `realPlayTimeInteracting` | 取れる |

### 4.2 その他（概要タブの下段）

| 統計 | 定義 |
|---|---|
| 敵の襲撃 | Σ コロニーの最大 `numRaidsEnemy` |
| 大きな脅威 | Σ コロニーの最大 `numThreatsQueued` |
| 入植者の死亡 | Σ コロニーの最大 `colonistsKilled` |
| 最長存続 | max コロニーの最大日数 |
| 単一コロニーの最高資産 | max コロニーの最大 `Wealth_Total` |
| 最大人口 | max コロニーの最大 `greatestPopulation`（キャラバンなども含むゲーム本体の値） |
| 最終資産の合計 | Σ コロニーの「`ticksGame` が最も大きい観測」での最後の `Wealth_Total`。同じ値の観測が複数あれば、現実の日時が新しい方を使う |

### 4.3 エンディングの種類

| 種類 | プレイ中の検知（§8.4） | 既存セーブの痕跡（§7.3） |
|---|---|---|
| 宇宙船 | 宇宙船の打ち上げ完了（船あり。旅の申し出の脱出船を含む） | `colonistsLaunched` ≥ 1 で、王族の昇天のクエストに `Success` が無い |
| 王族の昇天 | `QuestPart_EndGame` で入植者が旅立った | 単独では判定しない（下の「旅立ち（種類不明）」） |
| 旅立ち（種類不明） | 使わない（プレイ中は種類が分かる） | `colonistsLaunched` ≥ 1 で、王族の昇天のクエストが `Success`。<br>要人だけを送り出してクエストが成功した後に宇宙船で旅立った場合と、王族の昇天とを、セーブの値では区別できないため |
| アーコネクサス | `ArchonexusCountdown.EndGame` | 取れない |
| セレブレックス・コア（回収） | `DeactivateCore(scavenging: true)` | メカハイブのクエストが `Success` で、機械族の `deactivated` が無い |
| セレブレックス・コア（破壊） | `DeactivateCore(scavenging: false)` | メカハイブのクエストが `Success` で、機械族の `deactivated` が真 |
| 虚無を受け入れた | `EmbraceTheVoid` | Anomaly の `levelDef` が `Embraced` |
| 虚無を断ち切った | `DisruptTheLink` | Anomaly の `levelDef` が `Disrupted` |
| その他 | クレジット表示のうち上のどれにも当たらないもの（他 MOD のエンディング） | 取れない |

- 開発モードの `ForceShipCountdown`（船なしで終わる）は、「宇宙船」として旅立ち 0 人で記録する。これは開発モード中にしか起きない。
- **セーブ内の一覧で説明できる痕跡は使わない。** MOD 導入後のセーブには、その流れで到達したエンディングの一覧（§8.1 の `lineageEndings`）が入っている。痕跡は、この一覧で説明できない分だけを残す。
  - 宇宙船・旅立ち（種類不明）の痕跡: 一覧に、宇宙船・王族の昇天・旅立ち（種類不明）のどれかがあれば使わない。
  - セレブレックス・コアの痕跡: 一覧に、回収か破壊があれば使わない。
  - Anomaly の痕跡: 一覧に、受け入れか断ち切りがあれば使わない。

  こうすると、プレイ中に記録したエンディング（開発モードのものを含む）が、後のセーブの痕跡として二重に数えられない。MOD 導入前のセーブ（一覧が無い）の痕跡は、そのまま過去の証拠として使う。

### 4.4 表示の規則

- 取れない値は 0 にせず「—」と出し、理由をツールチップに出す。
- 各数値のツールチップには、「何コロニー分から計算したか」と「欠けている部分」を出す。
- 開発モード中に記録したエンディングは、設定がオフのとき一覧に出さず、合計にも含めない。
  - その場合、そのコロニーの旅立った人数は、次の 2 つの大きい方で数える。
    - max(0, 最大 `colonistsLaunched` − 開発モードの記録の旅立ち人数の合計)
    - 開発モード以外の記録の旅立ち人数の合計

    観測値には開発モードで旅立たせた人数も含まれるので、その分を差し引く。開発モードの記録が別の流れのものだった場合は少なめになるが、多く数えることはない。
  - 開発モード中のエンディングが無いコロニーは、§4.1 の式のまま数える。

## 5. 全体構成

### 5.1 部品

| 部品 | 層 | 役割 |
|---|---|---|
| `SaveReader` | 中核（.NET のみ） | 1 つの `.rws` を XmlReader で先頭から順に読み、`SaveObservation` を返す |
| `CampaignMatcher` | 中核 | 観測とプレイ中の記録をコロニーにまとめる（§7.4） |
| `ProfileStore` | 中核 | 記録ファイルの読み書き、バックアップ、形式バージョン（§6） |
| `StatsCalculator` | 中核 | §4 の数字を計算する |
| `LiveRecorder` | ゲーム接続 | GameComponent と、エンディング用の Harmony パッチ（§8） |
| `ImportRunner` | ゲーム接続 | 裏スレッドでの取り込みの開始・中止・進捗（§7.5） |
| `UI` | ゲーム接続 | メニューボタン、統計ウィンドウ、MOD 設定（§9） |

## 6. データと記録ファイル

### 6.1 置き場所と形式

- `<SaveData>/RimworldStatistics/profile.json` に置く。`<SaveData>` は `GenFilePaths.SaveDataFolderPath`。
- 形式は JSON で、`System.Text.Json` を使う。ゲームの Scribe は使わない。
- MOD の設定は、ゲーム標準の `ModSettings` に保存する（`Config` フォルダ）。

### 6.2 中身

コロニーは保存しない。読み込むたびに ①〜④ から組み立て直す。

```jsonc
{
  "schemaVersion": 1,
  "saveObservations": [            // ① セーブを読んだ結果。追記だけで置き換えない（§7.1）。元ファイルが消えても残す
    {
      "fileName": "…", "fileSize": 0, "lastWriteUtc": "…", "readerVersion": 1, "superseded": false,
      "status": "ok | unidentifiable | error", "errorReason": null,
      "gameVersion": "1.6.4566 rev607", "modCount": 0,
      "identity": {
        "seedString": "…", "persistentRandomValue": 0, "startingTile": "221529,0",
        "gameStartAbsTick": 0, "firstWealthBits": 0, "startingPawnIds": ["Thing_Human123"],
        "modCampaignId": null
      },
      "values": {
        "ticksGame": 0, "realPlayTime": 0.0, "numRaidsEnemy": 0, "numThreatsQueued": 0,
        "colonistsKilled": 0, "colonistsLaunched": 0, "greatestPopulation": 3,
        "wealthMax": 0.0, "wealthLast": 0.0, "wealthPoints": 0
      },
      "endingTraces": ["RoyalAscent"],
      "display": {
        "factionName": "…", "worldName": "…", "scenario": "…", "storyteller": "…",
        "difficulty": "…", "permadeath": false
      }
    }
  ],
  "liveCampaigns": [               // ② MOD のコロニー ID ごと
    { "campaignId": "guid", "identity": { /* ① と同じ形 */ },
      "max": { /* values と同じ形（最大値） */ }, "latest": { /* 最新の観測 */ },
      "display": { }, "lastSavedUtc": "…" }
  ],
  "endingEvents": [                // ③ 重複を除くキー = (campaignId, type, ordinal)
    { "campaignId": "guid", "type": "Ship", "ordinal": 0, "source": "live | seededTrace",
      "ticksGame": 0, "realTimeUtc": "…", "departed": 0, "launchedTotalAfter": 0,
      "devMode": false, "gameVersion": "…", "creditsExcerpt": null }
  ],
  "userDecisions": {               // ④
    "excludedCampaignKeys": [], "manualMerges": [], "manualSplits": []
  },
  "colonyKeys": [                  // 判定キーが重なったときだけ使う台帳（下記）
    { "key": "fp:<hash>#2", "fingerprintHash": "<hash>", "startingPawnIds": ["Thing_Human124"] }
  ],
  "importState": { "lastScanUtc": "…" }
}
```

- `firstWealthBits` は、`Wealth_Total` の先頭値を float32 のビット列のまま持つ。比較は完全一致で行う。
- `startingTile` は「タイル番号,層番号」に揃える。1.5 の形式には `,0` を補う。
- コロニーキーの作り方:
  - 判定キーが作れるコロニーは、判定キーのハッシュから `fp:<hash>` を作る。
  - まれに、同じ判定キーで初期入植者が包含関係にない別コロニーがある。その場合は、見つけた順に `fp:<hash>#2`、`#3`… を割り当て、`colonyKeys` に保存する（最初の 1 つは `fp:<hash>` のまま）。
    - 台帳の各項目は、判定キーのハッシュと初期入植者 ID の和集合を持つ。次回からは、初期入植者の包含関係で同じ項目に対応付け、和集合を更新する。
    - 番号は保存したものを使い続けるので、最小 ID などの値の偶然の一致でキーが重なることはない。後から古いセーブが見つかっても、キーは変わらない。
    - 1 つのコロニーが台帳の複数の項目に当たることがある。例えば、別々だった分岐が、後から見つかった祖先のセーブで 1 つにまとまった場合。そのときは、番号の最も小さいキー（番号なしが最小）を使い、他のキーは別名として扱う。④ の指定は、別名に付いていても同じコロニーに当てる。
  - 判定キーが作れないコロニーは `id:<guid>` を使う。
  - ④ の指定は、このコロニーキーで参照する。
- ③ は `(campaignId, type, ordinal)` で重複を除いて保存する。同じキーが既にあれば新しく追加はしないが、次の 2 点だけ既存の記録を更新する。
  - 既存が `devMode: true` で、新しい記録が `devMode: false` なら `false` にする。開発モードで先に達成したエンディングを、通常プレイで達成し直したときに隠さないため。
  - `departed` と `launchedTotalAfter` は大きい方を残す。
- 数えるときは、コロニーにまとめた後の `(type, ordinal)` の種類数で数える（§4.1）。同じコロニーに複数の ID が混ざっても、同じエンディングを二重に数えないため。同じ `(type, ordinal)` の記録が複数あれば、1 件でも `devMode: false` があれば通常の記録として扱う。

### 6.3 書き込み

- **タイミング:** エンディングを記録した直後（同期）、ゲームのセーブ後（裏）、タイトル画面へ戻ったとき、取り込みの完了時。
- **手順:** 一時ファイルに書いてから、`File.Replace` で置き換える。直前 3 世代を `profile.json.bak1`〜`bak3` として残す。
- **読み込みに失敗したら:** `bak1` から順に試す。すべて失敗したら空の状態で始める。壊れたファイルは `profile.json.corrupt-<日時>` に名前を変えて残す。
- **同時に書かない:** 書き込みは鍵をかけて 1 つずつ行う。画面は、最後に完成した写しを読む。

## 7. 既存セーブの取り込み

### 7.1 対象とタイミング

- 対象は `SavedGamesFolderPath` 直下の `*.rws` と `*.rws.old`。RimSaves のフォルダ分けは、ファイル名の接頭辞なので、これで漏れない。
- タイトル画面を最初に表示したとき、自動で取り込む（設定でオフにできる）。統計ウィンドウの「再スキャン」でも取り込む。
- ファイル名・サイズ・更新日時が ① と同じファイルは読まない。
- **同じファイル名でサイズか更新日時が変わっていたら**（自動セーブ枠の使い回しや、同じ名前での上書き）、新しい観測を追加する。古い観測は置き換えず、`superseded: true` にして残す。自動セーブの枠はコロニーをまたいで使い回されるので、置き換えると前のコロニーの記録が消えるため。
  - 古い観測を消してよいのは、新しい観測が同じコロニー（同じコロニー ID、または判定キーが一致し初期入植者が包含関係）で、かつ全項目で古い観測以上のときだけとする。全項目とは、`ticksGame`、実プレイ時間、各カウンタ、`wealthMax`、痕跡の集合。この場合は消しても集計結果が変わらない。
- 読み取りに使う処理の版（`readerVersion`）が上がったときは、残っているファイルをすべて読み直し、同じ内容（名前・サイズ・更新日時が同じ）の古い観測と入れ替える。元ファイルが無いものや、内容が変わって `superseded` になったものは、古い版で読んだ ① をそのまま残す。
- ファイルは読み取り専用で開く（`FileShare.ReadWrite | FileShare.Delete`）。セーブには一切書き込まない。

### 7.2 読む項目

- 調査 §3.1 の表の項目を読む。`world/maps` などの不要な部分は、XmlReader の Skip で中身を解釈せずに飛ばす。
- 欠けている要素には、ゲームの既定値を当てる。
- `history` は、`Wealth_Total` の系列から先頭値・最大値・最終値・点数だけを残す。
- `components` では、MOD のコロニー ID と `lineageEndings`（§4.3 の痕跡の除外に使う）、および Anomaly の `levelDef` を読む。

### 7.3 エンディングの痕跡

§4.3 の右列の条件で判定する。痕跡は「少なくとも 1 回」を意味し、回数は表さない。

### 7.4 コロニーへのまとめ方

上から順に当てはめる。

1. **MOD のコロニー ID** が観測にあれば、その ID のコロニーにする。
2. **判定キー**（`seedString` + `persistentRandomValue` + `startingTile` + `gameStartAbsTick` + `firstWealthBits`）が一致し、かつ `startingPawnIds` が包含関係（一方が他方を含む）にあれば、同じコロニーにする。
3. どれにも当たらなければ、新しいコロニーにする。

補足:
- まとめ方は、毎回すべての観測から組み立て直す。取り込みの順序で結果が変わらないようにするため。
  - 処理する順は、初期入植者の数が多い順にする。祖先のセーブ（減る前の入植者を持つ）が先に来る。
  - 比べる相手は、そのコロニーにまとめた初期入植者の和集合にする。
  - その結果、分岐したセーブ（例: {A,B} と {A,C}）は、共通の祖先（{A,B,C}）があれば 1 つにまとまる。祖先が後のスキャンで見つかった場合も、次の組み立てで 1 つにまとまる。
- ② の各コロニー ID は、自分の判定キーも持つ。2 で一致すれば、セーブから読んだ観測と同じコロニーになる。
- 判定キーの一部（シード、開始時刻、資産の系列）が欠けている観測は、`unidentifiable` として合計から外し、一覧に理由を出す。
- パーマデスのセーブ名、セーブのファイル名、勢力名は、判定に使わない（調査 §6）。
- ④ の手動統合は、1〜3 の結果に最後に適用する。手動分割は、v1 では記録の形だけを用意し、適用しない。何をどの単位で分けるかは、操作画面を作る段階で決める（§13）。

### 7.5 取り込み中の動き

- `ImportRunner` が、メインスレッドで `SavedGamesFolderPath` と前回の ① を取得してから、`Task` で `SaveReader` を走らせる。
- 裏スレッドでは、ゲーム本体の API を呼ばない。
- 進捗（全体の件数、読んだ件数、失敗の件数、読んでいるファイル名）を画面に出す。「中止」もできる。
- ゲームを開始・ロードしたら（`Current.ProgramState` が `Entry` でなくなったら）中断する。読み終えた分は保存し、次にタイトル画面へ戻ったとき続きから読む。
- 失敗したファイルは、理由を残して次回も試す。
- 消えたファイルの ① は残し、「元ファイルなし」と表示する。

## 8. プレイ中の記録

### 8.1 セーブに持たせる情報

`GameComponent_RimworldStatistics`（コンストラクタは `(Game game)`）が、次の 3 つを `ExposeData` で保存する。
- `campaignId`（GUID 文字列）
- `lineageEndings`（この流れで到達したエンディングの一覧。各要素は種類・何回目か・`ticksGame`）
- `dataVersion`

### 8.2 コロニー ID を決める

- **`StartedNewGame`:** 新しい GUID を作る。
- **`LoadedGame` で `campaignId` が空のとき（MOD 導入前のセーブ）:**
  1. ゲーム中の状態から判定キーを作る（調査 §5 の値）。
  2. ② に、判定キーが一致し初期入植者が包含関係にあるコロニー ID があれば、それを使う。同じコロニーの導入前セーブを何度ロードしても、ID が増えないようにするため。無ければ新しい GUID を付け、② に判定キーと一緒に登録する。
  3. ゲーム中の状態から §4.3 の痕跡を判定する。痕跡がある種類は、`lineageEndings` に「0 回目」として入れ、③ にも `source: seededTrace` で入れる。こうすると、導入後に同じ種類を新たに達成したとき 2 回目になる。
- **`LoadedGame` で `campaignId` があるとき:** その ID を使う。

### 8.3 セーブのたびに更新

- `ExposeData` の保存時（手動・自動セーブの両方）に、次の値を読み取る。
  - `ticksGame`、`realPlayTime`、`statsRecord` の各値
  - `Wealth_Total` の最大値と最新値
  - 判定キー、勢力名などの表示用の値
- 読み取った値で ② を更新し、書き込みは裏で行う。
- 例外はすべて受け止め、ログに 1 回だけ出す。保存処理は止めない。
- `GameComponentTick` は使わない。

### 8.4 エンディングの検知と記録

- **記録する場所:** `GameVictoryUtility.ShowCredits` の Postfix。種類は、直前の Prefix が設定した「文脈」で決める。

| Prefix の対象 | 文脈 |
|---|---|
| `ShipCountdown.CountdownEnded` | `shipRoot` があれば「宇宙船」（旅立ち人数は `colonistsLaunched` の前後の差）。`customLaunchString` があり、直前に `QuestPart_EndGame` 側で記録済みなら「既に記録済み」（二重に記録しない）。`customLaunchString` があるのに記録が無ければ「その他」（QuestPart 側の差し込みに失敗した場合など）。どちらも無ければ「宇宙船」（0 人、開発モードの `ForceShipCountdown`） |
| `ArchonexusCountdown.EndGame` | 「アーコネクサス」（人数は前後の差） |
| `CompCerebrexCore.DeactivateCore(bool scavenging)` | 「回収」または「破壊」 |
| `VoidAwakeningUtility.EmbraceTheVoid` / `DisruptTheLink` | それぞれの種類 |
| 文脈なし | 「その他」。クレジット本文の先頭 1 行を `creditsExcerpt` に残す |

- **王族の昇天だけは、入植者が旅立った時点で記録する。**
  - 対象は `QuestPart_EndGame.Notify_QuestSignalReceived`。呼び出し前に `ShipCountdown.CountingDown` が偽で、呼び出し後に真になったときに記録する。人数は `colonistsLaunched` の前後の差とする。
  - 入植者はすでに消えているので、その後のカウントダウン中にゲームを終えても取りこぼさない。
  - 種類は、その QuestPart のクエストの `root` で決める。`EndGame_RoyalAscent` なら「王族の昇天」、それ以外（他 MOD のクエスト）なら「その他」とし、`creditsExcerpt` にクエストの defName を残す。
- **記録の手順:**
  1. `ordinal` を、`lineageEndings` にある同じ種類の数で決める。
  2. `lineageEndings` に追加する。
  3. ③ に `(campaignId, type, ordinal)` が無ければ追加する。有れば、§6.2 の規則で更新する。
  4. 記録した時点の `Find.StoryWatcher.statsRecord.colonistsLaunched`（エンディング後の累計）を、③ の `launchedTotalAfter` と ② の最大値に反映する。アーコネクサスのように後でセーブされないエンディングでも、導入前からの累計を数え落とさないため。
  5. すぐに記録ファイルへ書き込む。
- **やり直したときの動き（D2）:** エンディング前のセーブをロードすると、`lineageEndings` にそのエンディングが無いので、同じ `ordinal` になる。③ に同じキーがあるので、増えない。
- **開発モード:** 記録時に `Prefs.DevMode` が真なら、`devMode: true` を付ける。
- **失敗したとき:** パッチ内の例外はすべて受け止める。失敗したパッチはそのセッションの間だけ止め、クレジット表示は妨げない。

### 8.5 MOD を外したとき

セーブに残った GameComponent は、本体が「クラスが見つからない」とログに出して読み飛ばす。ロードとプレイは続けられる。

## 9. 画面

### 9.1 入口

- `OptionListingUtility.DrawOptionListing` の Prefix で、`Current.ProgramState == ProgramState.Entry` のときだけ、「オプション」（`"Options".Translate()`）の直前に「通算統計」を足す。
- メインメニューはボタン一覧を 2 回描く（本体の一覧と Web リンクの一覧）。足すのは「オプション」の項目を含むリストだけにする。
- 同じ処理に Prefix を当てる他 MOD（RimSaves）と共存させる。リストに要素を足すだけで、他の要素は消さない。

### 9.2 統計ウィンドウ（Verse.Window、4 タブ）

1. **概要:** §4.1 を上段に大きく、§4.2 を下段に出す。§4.4 のツールチップを付ける。
2. **エンディング:** 日時、コロニー、種類、何回目か、旅立った人数、出所（プレイ中の記録／セーブの痕跡）。開発モード中のものは、設定がオンのときだけ出す。
3. **コロニー:**
   - 名前、ワールド、シナリオとストーリーテラー
   - 日数、最高資産、最終資産、襲撃、死亡、エンディング
   - 遊んだ版、セーブ数、最後に遊んだ日（ファイルの更新日時）、元ファイルの有無
   - 列で並べ替えられる。行を選ぶと元になったセーブの一覧を出す。行ごとに「合計から外す」チェックを付ける。
   - 表示名は、`ticksGame` が最も大きい観測の勢力名を使う。勢力名が無ければ「（未命名）＋ワールド名」とする。
4. **取り込み状況:**
   - 最後に読んだ日時、件数（読んだ／読み飛ばした／失敗）
   - 失敗と識別不可の理由の一覧
   - 「再スキャン」、進捗バー、「中止」
   - 記録ファイルの場所、バックアップの状態

本体標準の UI 部品を使い、CustomUIScales などの拡大縮小に従う。文言はすべて翻訳キーにする。

### 9.3 MOD 設定

| 設定 | 既定 |
|---|---|
| 開発モード中の記録を表示し、合計に含める | オフ |
| タイトル画面で自動的に取り込む | オン |

## 10. 異常時・性能・互換性

- **パッチ:** Harmony は Prefix と Postfix だけを使い、Transpiler は使わない。パッチの中の例外は外へ出さない。
- **セーブ:** 1 件の解析に失敗しても、残りを続ける。セーブには書き込まない。
- **性能の目標:**

| 項目 | 目標 |
|---|---|
| 通常プレイ | 毎ティックの処理はゼロ |
| セーブ 1 回あたりの追加時間 | 50ms 未満 |
| タイトル画面 | MOD が原因で 100ms 以上止まるフレームを作らない |
| 初回の取り込み時間 | 測って記録する（49 件で 60 秒以内を目安とする） |

- **特に確かめる MOD:** RimSaves、HugsLib、Dubs Mint Menus、CustomUIScales、Performance Optimizer、Dubs Performance Analyzer、Visual Exceptions。

## 11. 検証

### 11.1 この環境での自動確認（ゲームは起動しない）

1. **中核の単体テスト**（合成した見本 XML を使う）
   - `SaveReader`: 既定値、開始タイルの 2 形式、`records` / `recordsDeflate`、クエストの状態と痕跡、コロニー ID、壊れた XML、途中で切れたファイル。
   - `CampaignMatcher`: 調査 §6 の例 A〜D、コロニー ID の優先、識別不可、判定キーが重なった場合の `colonyKeys`（最小 ID が同じ 2 コロニーを含む）。
   - `ProfileStore`: 置き換え方式の書き込み、3 世代バックアップ、破損からの復旧、形式バージョン、同じファイル名に別コロニーが上書きした場合の観測の保持と、消してよい観測の判定。
   - `StatsCalculator`: 最大値の規則、最終資産の規則、D2 の重複排除、`seededTrace`、除外、開発モード設定。
     - あわせて確かめること: 開発モードで先に達成した記録を通常プレイで達成し直したときの更新、`launchedTotalAfter` による導入前からの累計、「旅立ち（種類不明）」の痕跡。
2. **実物セーブでの照合**（保存場所を環境変数で指定したときだけ動く）
   - R2 の 49 件をすべて読めること。
   - 33 コロニー、2,262.1 日などが、調査 §7 の値と一致すること。
   - C# での読み取り時間を記録する。
3. **ビルドと参照の確認**
   - 1.7.4985 の DLL と Harmony 1.7 に対してコンパイルが通ること。
   - 監査済み索引の `MetadataAudit` と `refcheck.py` で、参照しているメンバーとパッチ対象が 1.7.4985 に存在すること。

### 11.2 利用者の PC での手動確認（手順書を `docs/` に置く）

1. 起動してエラーが出ないこと。RimSaves と一緒でもボタンが出ること。`Player.log` でゲームの版を控える。
2. 取り込みの進捗が出て、合計が 11.1-2 と一致すること。セーブが増えていれば、その差を説明できること。
3. 新しいゲームを始めてセーブすると、コロニーが増え、値が動くこと。
4. MOD 導入前のセーブをロードしてセーブしても、コロニーが増えず、既存のコロニーにまとまること。
5. 開発モードの「Force start ship」（船コアと、入植者が入った冷凍睡眠棺を置く）で、次を確かめる。
   - 「宇宙船」として、`devMode` 付きで記録されること。
   - 設定でオン・オフが切り替わること。
   - エンディング前のセーブでやり直しても、回数が増えないこと。
   - 続けて 2 回目を打ち上げると、増えること。
   - 王族の昇天・アーコネクサス・セレブレックス・コアは、開発ツールで再現できる範囲で確かめる。
6. Dubs Performance Analyzer で、毎ティックの処理が無いこと、セーブ時の追加時間が目標内であることを確かめる。
7. MOD を外しても、MOD 付きで作ったセーブをロードできること。

## 12. 受け入れ条件

1. タイトル画面から、どのセーブもロードせずに、§4 の統計が表示される。
2. R2 の 49 件で、コロニー数 33、通算 2,262.1 日、実プレイ 263.9 時間、襲撃 190、死亡 29、最高資産の合計 4,364,583 になる（表示の丸めは除く）。
3. 同じセーブを何度取り込んでも、数値が変わらない。
4. 取り込み済みのセーブを消して再スキャンしても、数値が減らない。自動セーブの枠などの同じファイル名に別のコロニーが上書きしても、前のコロニーの数値が減らない。
5. MOD 導入前のセーブをロードしてセーブしても、コロニー数が増えない。
6. エンディング前のセーブでやり直しても回数が増えず、同じ流れでの 2 回目は増える。
7. 開発モード中のエンディングは、設定がオフなら一覧にも合計にも出ず、オンなら出る。
8. 取れない値は「—」と理由が出て、0 とは表示されない。
9. 壊れたセーブがあっても、他のセーブは取り込まれる。取り込みの前後で、どのセーブのハッシュも変わらない。
10. 利用者の MOD 構成（RimSaves を含む）で、ボタンとセーブ一覧が両方動く。
11. §10 の性能目標を満たす。
12. 記録ファイルが壊れても、バックアップから復旧する。
