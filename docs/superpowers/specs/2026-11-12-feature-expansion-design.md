## 1. 目的と範囲

全コロニー横断の通算記録を「見やすく・選んで・比べて・持ち出して・守れる」ようにし、他MODの固有システムの記録を本体の共通取得処理で増やす。対象は次の8分野。

| # | 分野 | この設計での位置づけ |
|---|---|---|
| 1 | 統計ウィンドウの表示改善 | 共通の表示部品（F4）を作り、既存5タブへ適用する |
| 2 | お気に入り統計・カスタム概要 | 概要タブに「お気に入り」欄を追加する |
| 3 | 複数コロニーの選択集計 | 集計範囲（F1）とコロニーグループ。比較表示は後段 |
| 4 | 統計取得状況の一覧化 | 分類（F5）と「取得状況」タブ、詳細統計の状態絞り込み |
| 5 | 歴代ランキングTOP10 | 順位表（F3）と「ランキング」タブ |
| 6 | CSVエクスポート | 現在の集計範囲の数値・順位・コロニー一覧を長形式CSVで出力 |
| 7 | プロフィールのバックアップ・復元 | タイトル画面からの手動バックアップ（zip）と検証付き復元 |
| 8 | 他MOD固有の統計拡張 | フレームワーク単位の本体内取得を優先。詳細は別紙 |

**範囲外**：リリース、Steam Workshop 更新、既存統計の意味変更、グラフ表示、単一セーブの最新状態だけを示す新しい表示、Anomaly の実ゲーム検証。

## 2. 不変条件（全機能共通）

1. 既存の統計ID（`MetricDefinition.Key`／`StoredKey`）、改訂番号、`SaveReader.Version`（現在17）、`Profile.CurrentSchemaVersion`（2）、チェックポイント形式（1）を変えない。分野8は**新しいキーを追加するだけ**で、既存キーの意味を変えない。
2. 欠測（`Unknown`）を0として表示・集計・出力しない。`Partial`／`Experimental`／`UnknownLegacy` を強い側へ昇格させない。CSVでも欠測は空欄で、状態列に理由を書く。
3. 新しい表示は「全コロニー横断」または「利用者が選んだコロニー群の横断」として提示する。単一セーブの最新状態だけを示す表示は追加しない（コロニー別の値は既存どおり代表観測の値として扱う）。
4. 過去の出来事を根拠なく復元しない。分野8の新しい取得は、有効化した後の確定イベントか保存時点の状態だけを記録する。
5. `profile.json` の既存データを削除・改変しない。お気に入り・グループなどの表示設定は `profile.json` に入れない（理由は §4.2）。
6. 取得元MODを外しても、保存済みの値と提供元定義（`ModMetricDescriptors`）を保持する。外した期間は欠測として扱う。
7. 性能：タイトル画面の描画（OnGUI）で全件の並べ替え・文字列生成・幅測定を毎回行わない。ゲーム中の新しいフックは確定点だけで、毎tickの走査・反射を追加しない。実験的取得は既定OFFで、OFF・対象MODなし・旧アドオン併用時はパッチを1件も適用しない（#117/#142 の方針）。
8. 公開SDK `RimworldStatistics.Api` の型・メンバーを変えない。
9. 翻訳キーは日本語・英語を同時に追加する（`tools/check_keys.sh`）。文字サイズ（`GameFont`）は原則として変えない。
10. 復元・出力などのファイル操作は、元のファイルを確認してから置き換え、失敗時に元へ戻せる手順にする。Cloudflare R2 は読み取りのみ。

## 4. 構成の比較と選択

### 4.1 全体構成

| 案 | 内容 | 評価 |
|---|---|---|
| A | 8分野を独立に実装 | 表の描画・範囲選択・状態判定が3〜4か所に重複する。不採用 |
| **B** | **共通基盤（F1〜F7）を小さく作り、各分野はその組合せにする** | 重複が最小。各基盤は Core の純粋関数として単体テストできる。**採用** |
| C | ウィンドウ全体を作り直す | 変更が大きく既存の挙動・手動確認をやり直すことになる。不採用 |

### 4.2 お気に入り・グループの保存先

| 案 | 評価 |
|---|---|
| `profile.json`（`UserDecisions` 等） | `ProfileStore.SameStatistics` は `importState` 以外の差分で自動バックアップ（bak1〜3）を回転させる。表示設定を3回変えるだけで統計の古い復旧点が押し出される。スキーマ互換の検討も増える。**不採用** |
| `RimworldStatistics/` に別ファイル | バックアップに入れやすいが、自前の原子的書き込みが要る。次点（採用案と入れ替えてよい） |
| **MOD設定（`ModSettings`）に JSON 文字列1件として保存** | RimWorld の保存処理をそのまま使える。形式は Core の型で検証でき、バックアップには `preferences.json` として同じ形式で入れられる。**採用**（別ファイル方式に変えてもよい） |

選択中の集計範囲はセッション中だけ覚え、起動のたびに「全コロニー」から始める（概要の数値が知らないうちにグループ合計になる誤読を避ける）。

### 4.3 集計範囲の実装

| 案 | 評価 |
|---|---|
| 計算前に範囲外のコロニーを一覧から除く | `MetricCalculator.Attach` が観測の帰属先を一覧から探すため、範囲外の観測が「帰属不明」になるか、別のコロニーへ誤って帰属しうる。**不採用（禁止）** |
| **全コロニーを残し、範囲外の印を付けて合計の対象から外す** | 除外（`Excluded`）と同じ経路で集計され、帰属判定は変わらない。**採用** |
| グループ専用の集計器を別に作る | 集計規則が二重になる。不採用 |

### 4.4 ランキングの実装

| 案 | 評価 |
|---|---|
| `cross.top10.*` などの定義を登録 | 定義数・翻訳キー・保存されない行が数百増え、既存IDの一覧と監査に影響する。不採用 |
| **コロニー別の既存の行から必要なときに順位表を作る** | 登録済み定義を増やさない。SDK提供の統計も自動で対象になる。**採用**。1位は既存 `cross.max.*` の保持者と一致することをテストで保証する |

### 4.5 その他の選択

- 取得状況：VerifyHarness の監査（開発用。Observed＝値がある、の意味）は利用者向けの分類としては流用しない。利用者向けの分類を Core に新設し、必要なら VerifyHarness 側が後から使う。
- CSV：横長（列＝コロニー）ではなく**長形式**（1行＝1値）。列数がコロニー数や内訳で変わらず、表計算でもスクリプトでも扱いやすい。
- バックアップ：フォルダのコピーではなく**1ファイルのzip**。持ち運び・別名保存が容易で、目録とハッシュで完全性を確かめられる。
- 他MOD：フレームワーク（VEF Outposts、VEF の能力を使う VPE、Vehicle Framework）は**本体の取得単位**として実装し、同じフレームワークを使う他MODも対象にする。既存の内蔵連携（Hospitality・DBH・SAU）は既存のSDK提供元をそのまま拡張する。

## 5. 共通基盤

各基盤は「ゲームに依存しない判定・計算」を `RimworldStatistics.Core` に置き、描画だけを `RimworldStatistics`（ゲーム側）に置く。既存の `StatisticsWindowLayout`（Core）と同じ考え方である。

### F1 集計範囲（分野2・3・4・5・6）

- 範囲は「全コロニー」か「保存したグループ」の2種類。全コロニーは現在の挙動と完全に同じ（除外したコロニーを数えない）。
- グループの範囲では、グループに含まれないコロニーに「範囲外」の印を付ける。**集計の対象＝除外されておらず、範囲外でもないコロニー**。帰属判定（`Attach`）・コロニーの組み立て（`CampaignMatcher`）には全コロニーを渡す。
- グループに入っていても除外したコロニーは数えない（除外は「数えない」という利用者の決定であり、範囲より優先する）。グループ編集画面ではその旨を表示する。
- グループは colony key の一覧で持つ。照合は除外と同じく `Colony.Key` と `AliasKeys` のどちらかに一致すればよい。見つからないキーは数えず、編集画面に「見つからないコロニー n件」と出し、削除できるようにする。
- `ProfileSession` のビューのキャッシュに範囲を加える。範囲別のビューは数件までに制限する（例：全コロニー＋直近3範囲）。コロニー別の行は範囲に依存しないので、全体ビューの行を再利用する最適化は計測で必要と分かった場合だけ行う。
- 表示：概要・詳細統計・ランキング・取得状況・CSV に適用する。エンディング・コロニー一覧は全コロニーのままとする。
- 現在の範囲は、ウィンドウ上部（タイトル行の右側）に常に表示し、そこから切り替える。

### F2 統計の参照と値の取得（分野2・5・6）

- 参照は統計キー（`MetricDefinition.Key`）の文字列。基本記録（v1 の通算日数・実プレイ時間・資産・襲撃数など）には、登録済みキーと衝突しない名前空間の仮キー（例：`basic.days`）を与える。登録済みキーに `basic.` で始まるものはない（2026-11-12 確認）。
- 参照から「範囲全体の値の行」「コロニー別の値の行」「表示名・説明・単位」を引く処理を1か所にまとめる。詳細統計の表示名・書式・ツールチップ（`DetailsTab.DefinitionLabel`・`Format`・`BuildTip`）を共通の場所へ移し、お気に入り・ランキング・取得状況・CSVで使う。
- 参照先がない（削除された統計など）場合は「不明な統計」として表示し、値を出さない。

### F3 順位表（分野5・6）

- 入力：参照する統計、範囲の集計対象コロニー、方向（大きい順・小さい順）。
- 対象：`Known` で有限の数値を持つコロニーだけ。`Unknown`・`NotApplicable`・数値なし（閾値未到達など）は順位に入れない（0とみなさない）。基本記録は、観測点を1つ以上持つコロニーだけを対象にする（観測点がなく0になっている値を順位に入れない）。
- 同値は同順位（1, 1, 3 …）。同順位内の並びはコロニーキー順（既存の `CrossColonyAggregator` の同率と同じ）。
- 各順位に、値・状態（Complete/Partial/保存時点）・証拠（Experimental 等）・記録時点（`ThroughTick`）を持たせる。
- `Partial` の値も順位に入れるが、状態の印を付け、順位表全体に「欠けを含む」と表示する（`cross.max.*` と同じ扱い）。
- テスト：`cross.max.<key>` の保持者と同率保持者が、同じ範囲の順位表の1位と一致すること。

### F4 表示部品（分野1・4・5・7）

- 列定義（最小幅・重み・右寄せ等）から列幅を決める純粋関数を Core に置く。合計の最小幅が使える幅を超えたら横スクロールにし、超えなければ重みで配分する。
- 表の描画部品：固定の見出し行、並べ替えの印、可視行だけの描画、セルの省略と「省略したセルだけ全文ツールチップ」、文字幅の測定結果のキャッシュ（データの版と言語が変わったときだけ作り直す）。
- 操作行の部品：ボタン幅を文字幅から決め（最小・最大あり）、入らなければ次の行へ折り返す。
- ツールチップは表示時に作る（`TooltipHandler.TipRegion(Rect, Func<string>, int)`、#145 と同じ）。
- 既存のコロニー一覧（#144）、詳細統計（#145）の挙動・並べ替え順・選択・スクロールは変えずに部品へ移す。

### F5 取得状況の分類（分野4・6）

統計ごと（範囲内）に次の3軸で分類する。判定はコロニー別の行から行い、ランキング系（派生）の定義は全体の行の `Valid`／`Targets` を使う。

| 軸 | 値 | 判定 |
|---|---|---|
| 取得の程度 | 取得済み／部分記録／未取得／対象外 | 対象外：対象コロニー0。未取得：測定コロニー0。部分記録：一部のコロニーだけ測定、または測定値に `Partial` がある、または記録開始が途中（`SinceTick > 0`）。取得済み：それ以外 |
| 検証 | 標準／実験的（未検証）／旧記録 | 標準：`Published`（取得単位を持たないか、検証済みの取得単位）。実験的：未検証の取得単位・SDK提供元、または証拠が `Experimental`/`Mixed`。旧記録：**取得単位を持つ**定義で、測定値の証拠に `UnknownLegacy` を含む。取得単位を持たない定義（セーブの記録など）は、`MetricCalculator.EvidenceFor` が既定で `UnknownLegacy` を返すため、証拠によらず「標準」とする |
| 今回の記録 | 記録中／設定OFF／DLCなし／対象MODなし／失敗／不要 | 取得単位を持つ定義だけ。ゲーム側の `MetricGates`・`ModsConfig` の状態を Core に渡して判定する。セーブファイルから読む定義は「不要」 |

- 取得元：`Provenance`、観測の種類、取得単位ID、提供元MODの packageId を表示する。
- 欠測の確認：未取得・部分のコロニー名の一覧（多い場合は件数と先頭数件）を表示時に作る。
- 「設定OFF」などの状態は今回のセッションの事実であり、過去の値の有無とは独立に表示する。

### F6 表示設定の保存（分野2・3・7）

- 形式：`{"version":1,"favorites":[…],"groups":[{"id":…,"name":…,"colonyKeys":[…]}]}`。読み込みは寛容に行い、不明なフィールドは無視、壊れていれば空の設定で始めてログに1回警告する（設定が壊れても統計の表示は止めない）。
- 上限の目安：お気に入り64件、グループ32件、グループ名64文字。
- 変更時に `Mod.WriteSettings()` で即時保存する。
- 同じ形式をバックアップの `preferences.json` に使う。

### F7 ファイル出力の共通処理（分野6・7）

- 出力先は `GenFilePaths.SaveDataFolderPath/RimworldStatistics/` の下の `exports/` と `backups/`。名前はUTC時刻で一意にし、既存のファイルを上書きしない。
- 一時ファイルに書いてフラッシュし、完成後に名前を変える。
- 完了後に保存先を表示し、「フォルダーを開く」（`Application.OpenURL`。1.7.4985 の `UnityStubs` に存在を確認済み、Waylith でフォルダが開くかは未確認）と「パスをコピー」（`GUIUtility.systemCopyBuffer`、存在を確認済み）を出す。開けない環境でもパスのコピーで代替できる。

### 6.3 分野3：複数コロニーの選択集計

**目的**　任意のコロニー群（例：同じシナリオ、同じMOD構成、特定の時期）の合計と比較を、既存の全コロニー集計と同じ規則で見る。

**仕様（段階1：範囲とグループ）**

**仕様（段階2：比較表示）**

**受入条件**
- [ ] 「全コロニー」の値は導入前と完全に一致する（既存テストが変更なしで通る）。

- [ ] グループの保存・名前変更・削除が再起動後も保たれる。見つからないキーで例外を出さない。

### 6.4 分野4：統計取得状況の一覧化

**目的**　どの統計が取れていて、どれが部分的・未取得・未検証か、何から取ったか、どのコロニーが欠けているかを一覧で確かめる。

**仕様**

**受入条件**

### 6.6 分野6：CSVエクスポート

**目的**　現在の範囲の統計・順位・コロニー一覧を、表計算や外部スクリプトで扱える形で持ち出す。

**仕様**
- 「データ管理」タブ（現「取り込み状況」）に「CSV出力」を置く。出力先は `exports/<UTC時刻>/`。
- 出力ファイル（すべて UTF-8 BOM付き、CRLF、RFC 4180 の引用）：

| ファイル | 1行の単位 | 主な列 |
|---|---|---|
| `summary.csv` | 範囲全体の1統計（内訳は1内訳） | scope, metric_key, breakdown, label, category, unit, aggregation, value, value_display, coverage, evidence, availability, verification, provenance, acquisition_unit, owner_mod, colonies_measured, colonies_target, holder_colony_key, holder_colony_name, since_day, through_day |
| `colony_metrics.csv` | 1コロニーの1統計（内訳は1内訳） | colony_key, colony_name, metric_key, breakdown, label, unit, value, coverage, evidence, since_day, through_day |
| `colonies.csv` | 1コロニー | colony_key, name, world, scenario, storyteller, difficulty, permadeath, excluded, in_scope, 基本記録の各値, saves, last_played_utc, game_versions |
| `rankings.csv` | 1統計の1順位 | metric_key, label, direction, rank, colony_key, colony_name, value, coverage, evidence |
| `endings.csv` | 1エンディング | time_utc, colony_key, colony_name, ending_type, ordinal, departed, source |
| `manifest.json` | 出力全体 | 作成時刻、MOD版、範囲、言語、行数、列の説明への参照 |

- 数値は不変カルチャ（小数点 `.`、桁区切りなし）。整数はそのまま、実数は往復可能な精度。欠測は空欄で、`coverage`／`availability` に理由。人が読む表示値（`value_display`）とラベルは現在の言語。
- `rankings.csv` は測定済みの全順位を出す（10件で切らない）。
- 文字列の列で先頭が `=` `+` `-` `@` のものは先頭に `'` を付ける（表計算の数式として解釈されないため。数値列には適用しない）。
- 翻訳済みラベルはメインスレッドで集め、ファイルの書き込みはバックグラウンドで行う。進捗と完了・失敗を表示する。

**受入条件**
- [ ] 書き出し処理（引用、BOM、改行、数値書式、欠測の空欄、数式対策）の単体テスト。
- [ ] 小さな合成プロフィールの出力が期待ファイルと一致する（ゴールデンテスト）。
- [ ] `summary.csv` の値が同じ範囲の詳細統計と一致し、`rankings.csv` の上位がランキングタブと一致する。
- [ ] 出力中に失敗しても不完全なフォルダを完成品として残さない（一時名のまま、または削除）。
- [ ] 3,000件の合成セーブ規模で出力時間と割り当て量を記録する（目安：数秒以内。超える場合は Issue に数値を残す）。

### 6.7 分野7：プロフィールのバックアップ・復元

**目的**　利用者が任意の時点で記録一式を保存し、壊れたとき・誤って取り込んだときに検証してから元へ戻せる。

**仕様（バックアップ）**
- 「データ管理」タブに「今すぐバックアップ」。タイトル画面でのみ実行でき、取り込み中は待つか中止を求める。
- 内容：`profile.json`、`checkpoint-archive/` の全ファイル、`preferences.json`（F6）、`manifest.json`（形式番号1、作成時刻、MOD版、プロフィールのスキーマ番号、各ファイルの相対パス・サイズ・SHA-256、コロニー数・観測数の要約）。
- 一貫性：`ProfileSession` の書き込みを止めた状態（未保存の変更を書き出した後、書き込みの排他を保持したまま）で `profile.json` と退避ファイルを読む。
- `backups/rws-backup-<UTC時刻>.zip.tmp` に書き、閉じた後で開き直して全ハッシュを確かめてから `.zip` に名前を変える。
- 自動の bak1〜3 とは別に保持し、自動では削除しない。一覧から利用者が削除できる（確認あり）。

**仕様（復元）**
- 一覧から選ぶ（`backups/` に置いたzipも一覧に出る）。復元前に検証する：zipが読める、目録がある、形式番号を知っている、全ハッシュが一致、`profile.json` が現行の読み込み処理で読める、スキーマ番号が現行以下。検証結果（作成時刻・MOD版・コロニー数・観測数）を確認画面に出す。
- スキーマ番号が現行より新しいバックアップは復元しない（現行版では読み取り専用でしか開けないため）。
- 手順：(1) 現在の状態を「復元前」バックアップとして同じ形式で保存し検証する。(2) 現在のセッションの未保存分を書き出して閉じる。(3) `profile.json.lock` を排他で開いた状態で、現在の `profile.json`・`.bak1〜3`・`.previous`・`checkpoint-archive/` を一時フォルダへ移す。(4) 検証済みの内容を同じボリュームの一時フォルダへ展開し、所定の場所へ移す。(5) 新しいセッションを読み込む。(4)(5)で失敗したら移した元のファイルを戻す。成功したら一時フォルダを消す。
- `preferences.json` は確認画面で「表示設定も戻す」を選んだときだけ適用する（既定はオン）。
- 復元はタイトル画面・取り込み停止中だけ。ゲーム中は統計ウィンドウ自体が開かない（`MainMenuButtonPatch` は `ProgramState.Entry` のときだけボタンを出す）。
- バックアップと復元はタイトル画面のデータ操作として取り込みと排他にする。復元前バックアップはディスクの書き込みロックを取得してから、ファイルの入れ替え直前に作成する。表示中のビューはセッションの参照が変わった時点で無効化する。
- セッションの入れ替え：`ProfileService` に、セッションを閉じて読み直す処理を加える。統計ウィンドウは入れ替えを検知してビューを捨てる。入れ替えが安全にできないと判明した場合は、「次回起動時に適用」の方式（起動時、セッションを読む前に入れ替える）に切り替えてよい。

**受入条件**
- [ ] バックアップ→プロフィール変更→復元で、`profile.json` と退避ファイルのバイト列が元に戻る（単体・結合テスト）。
- [ ] ハッシュ不一致・目録なし・zip破損・新しいスキーマ・`profile.json` 破損のバックアップを復元しない。
- [ ] 復元の途中で失敗させたとき（展開後の移動失敗など）、元のファイルが元の場所に戻る。
- [ ] 復元前バックアップが必ず作られ、それ自体を復元できる。
- [ ] 既存の bak1〜3 の回転・破損ファイル退避・`profile.v1.json` の挙動は変わらない（既存テスト）。
- [ ] 1,000件規模の退避ファイルを含む合成データでバックアップ時間を記録する。

### 6.8 分野8：他MOD固有の統計拡張

詳細は[別紙](2026-11-12-feature-expansion-mod-statistics.md)。要点：

- **本体の共通取得処理に統合する**：取得単位（`AcquisitionUnits`）・取得ゲート（`MetricGates`）・`MetricAdapter` によるパッチの遅延適用・保存時点の読み取り（`SavedStateMetricReader`）を使う。対象MODの型は名前で解決し、DLLを参照しない。
- 対象MODがない・版が合わない・型やメソッドが見つからないときは、その取得単位だけを閉じる（他を止めない）。
- 新しい統計はすべて実験的・既定OFF。有効化前の出来事は復元しない。
- 優先順：VPE → VEF Outposts（VOE）→ Hospitality → Dubs Bad Hygiene → Vehicle Framework → Smart Apparel Upgrade → その他候補（Vanilla Trading Expanded など、調査のみ）。

**共通の受入条件**
- [ ] 対象MODなし・取得OFFでパッチ0件、ONで想定どおりのパッチ数（`#117` と同じ確認）。
- [ ] 重複計上しない（例：VPE の詠唱と本体の `royalty.psycasts`、Outpost の生産と製作・収穫の記録）。
- [ ] 取得元MODを外して保存・再読込しても、記録済みの値が残る（既存の `ModMetricPersistenceTests` と同じ観点）。
- [ ] フック対象の静的確認（型・メソッドの存在。可能ならR2の該当版DLL）と、RWMT の A+B（対象MODあり・なし）を行う。

```text
F7 出力共通 ──> 分野6 / 分野7
分野8 はUI側と独立（新しい統計は既存の表示・新しいランキング・取得状況に自動で現れる）
```

## 9. リスクと対策

| リスク | 対策 |
|---|---|
| 範囲の実装で観測の帰属が変わる | 範囲外のコロニーを一覧から消さない（§4.3）。帰属件数のテスト |
| ランキングの1位と既存の `cross.max.*` の食い違い | 同じ有効値の判定を使い、一致テストを置く |
| 復元の途中失敗でデータを失う | 復元前バックアップ、移動による入れ替え、失敗時の巻き戻し、ロックファイル |
| 表示設定の保存でバックアップが押し出される | 表示設定を `profile.json` に入れない（§4.2） |
| 7タブ化でタブが入らない | 英語で幅を確認。必要ならタブ統合 |
| UIの見た目を自動テストできない | 計算部分を Core に分けて単体テスト。見た目は手動確認（§10） |
| CSVの巨大化 | 長形式で行数はコロニー×統計×内訳。3,000セーブ規模で計測 |
| 他MODの版の違い・非公開バイナリ | 型・メソッドを名前で解決し、見つからなければその単位だけ閉じる。版ごとに静的確認 |
| 他MODのフックによるTPS低下 | 確定点の低頻度フックのみ。毎tickの処理を入れない。RWMT と手動で比較 |

## 10. 未確定事項と確認方法

| 区分 | 項目 | 確認方法・判断時期 |
|---|---|---|
| 実装時に判断 | タブ名・配置、カードの寸法、列の最小幅、グループ数の上限、ビューのキャッシュ件数、`ReorderableWidget` の利用、ウィンドウのサイズ変更 | 実装PRで決め、PR本文に記録 |
| 実装時に判断 | 表示設定を `ModSettings` と別ファイルのどちらに置くか（§4.2） | どちらでも F6 の形式は同じ |
| 実ゲーム確認が必要 | 文字の重なり・省略・ツールチップ（日英・4サイズ・UIスケール） | 所有者の手動確認（`docs/manual-test-checklist.md` に追記）。RWMT の現行ホストは描画しないため対象外（描画の試作 W2 は非公開で未製品化） |
| 実ゲーム確認が必要 | `Application.OpenURL` でフォルダが開くか（Waylith） | 手動確認。開かなくてもパスのコピーで代替 |
| 実ゲーム確認が必要 | 復元後のセッション入れ替え中に他の処理が古いセッションを使わないか | 手動確認＋結合テスト。問題があれば「次回起動時に適用」へ切り替え |
| 実ゲーム確認が必要 | 分野8の各フックの数値の正しさ・TPS | 所有者の手動確認と VerifyHarness。RWMT は MOD読込とパッチ登録（A+B）まで |
| 追加調査が必要 | 分野8：Vehicle Framework の1.7 DLL の入手、VEF の `Ability.Cast` の呼び出し回数、VEF Outposts の生産経路のIL、Hospitality の売買の引数、DBH の完了判定、SAU の成功判定の方法 | 別紙の各節 |

Anomaly の実ゲーム検証は行わない。RimWorld 1.7 のマイナー版の差（1.7.4985 と 1.7.5000 など）は、具体的な差が確認されない限り同一として扱う。
