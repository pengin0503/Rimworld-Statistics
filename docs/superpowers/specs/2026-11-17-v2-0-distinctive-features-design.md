## 0. 目的と採否

v2.0.0を「数値一覧を見るMOD」から「過去の各コロニーを、保存済みの証拠から振り返り、違いを説明できる統計MOD」へ拡張する。単に現行のランキング・グラフ・イベントログを別画面に複製するのではなく、全セーブ横断と正確な履歴の取扱いを差別化の中心にする。

| ID | 機能 | 優先 | 採否 |
| --- | --- | --- | --- |
| V2-B | **セーブの系統・分岐を閲覧する** | P0 | 採用 |
| V2-C | **コロニーの総括レポート** | P0 | 採用 |
| V2-A | **確定記録のコロニー年表** | P1 | 条件付き採用：一般的な日記や全ログ記録を避ける |
| V2-D | **コロニー単位の散布図** | P2 | 採用。ただし記録の比較可能性を優先 |
| V2-E | **全コロニーの自己ベスト更新履歴** | P3 | 条件付き。既存ランキングの単なる言い換えなら見送る |
| 除外 | 実績解除・ポイント・報酬、通常のイベント日記、セーブ整理・削除 | — | 既存MODと役割が重なるため採用しない |

**これらは実装前候補である。** 開発がv2.0.0に到達するには、既存Issueの修正と新機能の受入れを別々に完了させる。機能数そのものをリリース条件にしない。

## 1. 全機能の不変条件

1. `Profile`、既存統計ID・改訂番号、外部SDK、セーブの識別規則、記録済みの観測、`MetricCoverage`を破壊しない。Unknown/Partial/NotApplicableと実測0を混同しない。
2. セーブの親子が確認できない場合は**「未確認」**として描画し、時刻順だけで線・枝を接続しない。兄弟枝や巻き戻しを単一の累計へ足さない。
3. 表示・集計の中心は**コロニーやセーブの横断的な実績**。現在の1セーブだけを表示する別MOD型のダッシュボードは作らない。
4. 過去に記録していない事象や発生日を推定して「確定」と書かない。古いセーブからの限定的な復元は、根拠と時点を画面に示す。
5. パフォーマンス：可能な範囲で既存Core計算・キャッシュ・可視行描画を再利用し、新規イベント記録に毎tick全件走査・広域反射を導入しない。読み込み・描画・ディスク増分をそれぞれ計測する。
6. MOD/DLCの有無・バージョン違いを理由に、別の記録が消えない。12言語の翻訳を実装時に維持し、狭いウィンドウでも情報を読めるようにする。
7. Cloudflare R2の内容は**参照のみ**。GitHub ReleaseやSteam Workshopを自動更新しない。ゲーム内確認は可能なら`pengin0503/RimWorld-for-mod-test`の1.7環境を使用する。
8. 本件において他MODの**コード・表現・アイコン・画面レイアウト**はコピーしない。一般的なグラフや年表の概念は独立実装する。

## 2. V2-B：セーブ系統と分岐の可視化（P0）

**利用者が得ること：** 同一コロニーの保存履歴のうち、どこまで親子関係が確定し、どこで別枝・巻き戻し・不明が生じているか理解できる。

- 既存`CheckpointAncestry`・`MetricObservation`・`HistoricalCounterIntervals`と保存済みの親子証拠を再利用した**読み取り専用の系統ビュー**を追加する。
- 節点＝根拠のあるチェックポイント／セーブ観測、辺＝確認済みの直接親子のみ。単なる同じコロニーID・年月日・保存名の一致では辺を引かない。
- 同じチェックポイントを含む複数セーブは、必要に応じて同一証拠への複数ファイル参照として扱い、別個の出来事として二重計上しない。
- 検証済み区間の統計変化は[Issue #307](https://github.com/pengin0503/Rimworld-Statistics/issues/307)の計算を可能なら参照し、未完なら先に重複しない計算インターフェースだけ設計する。
- 点を選択して取得時点・証拠の出典・記録状態・前後の比較へ移動する。親不明・欠落・衝突は明示する。
- 絶対に行わない：セーブを削除・リネーム・移動・上書きする操作、ユーザーの任意なセーブ結合作業、推定親子の確定表示。

**受入条件：** 直系／同時刻の同一証拠／兄弟分岐／巻き戻し／親欠落／アーカイブ復元／別MOD構成を区別できる。根拠なしの実線なし。大規模コロニーでは必要な節点だけ描画する。

## 3. V2-C：コロニー総括レポート（P0）

**利用者が得ること：** 過去の一つのコロニーの生涯実績を見渡し、他コロニーとの差を1画面で確認できる。

- 既存`StatsView`、`MetricLookup`、`MetricRankings`、`ViewScope`、表示設定・翻訳を利用して、各コロニーについて「概要」「重要記録」「全体での位置」「記録の信頼範囲」「関連グラフへの移動」を構成する。
- 新しい独立した累計の計算エンジンは作らず、**既存の統計と同じ定義・集計規則**を用いる。
- 記録がある場合だけ最大資産・生存日数・加入・死亡・襲撃・エンディング等を出す。未知は空欄/不明、観測済み0とは区別。異なる性質の最高値・時点値・累積値を混ぜて合計しない。
- 表示例：コロニー名／経過ゲーム内日数／最大資産／累計の対象期間／他コロニー内順位／記録範囲／クリックで統計グラフ、など。対応MOD統計は必要に応じて自然に追加される構造。
- **任意の静的HTMLエクスポート**は後段の独立タスク。既存CSVを変更せず、新しいファイルは値・観測範囲・出典・生成元バージョンを含める。HTMLエスケープ、ファイル名無害化、出力失敗時の不完全ファイル防止は必須。
- 他MODの現在時点ダッシュボードや個人ランキングとは異なる、**セーブ横断の過去実績・出典に特化**させる。

**受入条件：** コロニー0/1/多数、未記録、部分記録、長いMOD統計名、エンディング未到達、複数枝、12言語、スコープ/除外設定を処理できる。レポート値と詳細統計は一致する。

## 4. V2-A：証拠ベースのコロニー記録年表（P1、条件付き）

**利用者が得ること：** セーブやコロニーを開き直さずに、**確定して記録できた主要な出来事**と統計の変化を年代順に辿れる。

- 汎用イベント日記や会話・戦闘ログの全文収集は対象外。初期版は**終了／入植者加入／死亡／研究完了**など、イベントが確定した時刻を既存フックから安全に得られる項目だけを対象候補にする（実装前に成功コールバックを再確認）。
- 履歴の要素を `type / colony / observedTick / evidenceSource / coverage / stableEventKey`（概念上のフィールド）として整理する。**すべての要素が取得できるとは仮定しない**。日時・重複排除キーを証明できない種類は、日付不明の集約記録として別枠に表示するか対象外にする。
- 旧セーブの既知統計から「ある日時に出来事が発生した」と逆算しない。保存時の総数変化は「X日からY日の間に差があった」という**区間記録**と区別する。
- すべてのイベントを永久に無制限保存しない。最大記録数・保存容量・整理規則・長期キャンペーン後の挙動を実装前に測り、記録を失う場合は範囲欠損を可視化する。
- 年表はセーブ系統に紐付け、重複チェックポイントを二重イベントにしない。必要に応じて重要イベントから詳細統計・グラフを開けるようにする。
- 既存RimWorldのHistoryタブを置換しない。お祝い・追悼・報酬・プレイへの介入も行わない。

**受入条件：** 同一イベントの保存やロード、セーブ分岐、別枝の再訪、MOD設定OFF/ON、異なるゲーム版、取得失敗を正確に区別する。時刻が不明な記録へ架空の日付を振らない。

## 5. V2-D：コロニー横断の散布図（P2）

**利用者が得ること：** 最大資産と襲撃回数など、異なる2指標についてコロニー群の分布を見られる。

- 既存の詳細統計で選べる2指標（X/Y）をコロニー単位の代表観測で組にして描く。点をクリックすると対応するコロニーの詳細とグラフへ移動できる。
- 異なる期間・観測元・累計とスナップショット・未取得を明示し、比較不能なら**点を除外し理由を示す**。欠測0埋めなし。
- 相関係数・回帰線は初版では対象外。まず利用者が誤解しない散布図だけを完成させ、統計的な要件が定義できた場合だけ後から追加する。
- 数値が巨大・負・ゼロ・同値多数でも軸と点の重複表示が壊れない。既存のコロニーグループや除外設定を尊重する。

**受入条件：** 全点の値が既存の比較表示と一致し、データ不足を相関なしと断定しない。元データを変更しない。

## 6. V2-E：全コロニーの自己ベスト更新履歴（P3、条件付き）

- 既存`ランキング`の別名となる「実績画面」は作らない。実装するなら、**過去の記録に対し、いつ確定した新記録かを追跡できる場合**の「記録更新履歴」に限定する。
- 新しい称号・達成解除通知・ポイント・ゲームイベント報酬は作らない。Vanilla Achievements Expandedの領域と不要に重複させない。
- 正確な更新時刻を証明できず、現状の最高値/順位表示と実質同じなら**不採用のまま終了**してよい。

## 7. 実装順序・レビューゲート

1. **B系統可視化**：既存証拠APIの棚卸し → 読み取り専用Coreモデル → UI → 分岐/重複/復元テスト。Issue #307の作業とAPI重複を調整する。
2. **Cコロニー総括**：既存数値を使ったCoreビュー → GUI → 12言語 → 必要性が確認されたらHTML出力。Bが完成していなくても独立実装可能。
3. **A年表**：現状の取得イベントと記録時刻の可否を証拠表に整理 → 必要最小限の永続化方式 → 確定イベントだけ追加 → 系統重複テスト。確証できないイベントは実装しない。
4. **D散布図**：既存統計参照と可否判定を再利用 → 描画 → 大量コロニーの最適化。
5. **E自己ベスト**：B/A/Cと既存ランキングの完成形を見て、価値が十分に異なる場合だけ着手。

### 共通検証

- Core単体テスト、既存CI、翻訳キー整合、実データの読み取り専用インポート。
- **分岐・巻き戻し・同一チェックポイントを含む別セーブ・未確認の親子**を負のケースとして必須にする。
- 既存画面の表示性能・プロフィールサイズを更新前後で同一条件比較。計測していないTPS改善を宣伝しない。
- 実ゲーム検証は実装可能部分がまとまってから可能な範囲で実施。確認できなかった点は別途明示し、進捗を止める理由にしない。
- 他AIが進行中のIssue修正と競合するファイルは同時編集を避け、最新mainに再基準化してから実装する。
