## 1. 範囲と段階

タイトル画面からコロニー横断のゲーム内記録を数値で見る。一次整理の維持122・統合201の323候補を追跡し、保留37・原則除外56は対象外。1候補が複数の数値を表す場合も、別名・内訳として共通の取得元を使う場合もある。

| Phase | 先に成立させる機能 | 成立条件 |
|---|---|---|
| A | 既存セーブの履歴要約、バニラカウンター、残存クエスト、詳細統計タブ | 38候補。対象版のXML・旧版試験を通過した範囲で表示 |
| B | 正常セーブ時の保存時点スナップショット | 35候補。ロスター、設備、在庫、研究、勢力ごとの個別ゲート |
| C | 成功セーブ単位の枝管理、少数の確定イベントから開始 | 195候補。基盤 → 研究 → 心情・死亡 → 取得ファミリー単位で追加 |
| D | 派生順位・DLC別統計 | 9候補をv1/Aから算出、45候補は個別ゲート、1候補は見送り |

設計判断として、旧セーブのストリーミング解析と将来の確定観測を併用する。旧XMLにない分類・計算はゲームの判定を保存時に利用する。生イベントの通しログ、グラフ、遠隔送信、セーブの直接書き換え、分岐選択画面は設けない。v1の4タブ・概要13数値・エンディングの即時記録・コロニー同定を維持する。Aだけで詳細画面を使用でき、BとCはAの基盤に独立して追加できる。DのランキングとDLCは、使う基礎統計だけに依存する。

## 2. 数値・保存の契約

### 値と来歴

`MetricRegistry` は対応を確認して出荷した出力の表示・解釈を登録する。登録後は、現在のDLC/Hookが無効でも定義を残す。ゲーム側の取得ゲートは独立し、その時点のDLC/Def/Harmony状態で今後の取得だけを止める。台帳キーを安定IDとして使用し、別名は正規キーを参照する。内訳のキーはゲーム内部のDef名/列挙値、人物はゲーム内の一意ID。保存ファイルにプレイ中の操作履歴やフルネームを新規保存しない。人物を表示するとき名前を安全に取得できる現在の状態のみ使い、名前がなければIDを表示する。単位・演算・依存・必要DLC・日本語/英語のキーは登録に含める。

`MetricValue` は測定結果の nullable 整数（Int64）または有限実数（double）、率/平均の分子と分母、必要なときだけ `bucket`・計測期間・点数を持つ。JSONは invariant culture、UTCは既存のISO 8601。0は対象範囲が成立した既知値。欠損時に0を生成しない。日数はゲームtickから、実時間はv1の実プレイ秒から算出する。負値を許すのは気温・友好度・純増・成長率等の符号付き出力のみ。オーバーフローや非有限値は該当出力のみ不明にする。

| 状態 | 意味 | 数値表示 |
|---|---|---|
| Complete | 定義した計測範囲を記録済み。バニラ累計は規定の範囲内 | 値、対象範囲 |
| Partial | 途中導入・途中欠落・非対応経路・分類不明・集計対象欠落あり | 取得範囲の値と注意。完全値のように表示しない |
| SnapshotOnly | セーブ時点の状態、残存クエスト、有限間隔の履歴上の観測 | 値と「保存時点」「履歴上」等の由来 |
| Unknown | 値・分母・必要な時刻等の根拠が不足 | — と理由 |
| NotApplicable | DLCなし等で定義上の対象外 | DLCが対象の範囲に一度もなければカテゴリを隠す。対象外コロニーは母数外 |

SnapshotOnlyのうち欠測のある値は `Partial` とし、元の種別を由来で残す。範囲と由来（`VanillaCounter / SaveHistory / SaveSnapshot / LiveAggregate`）は状態と別。旧セーブのDLCは `meta/modIds` が明示された場合にだけ判定。現行DLC構成で旧記録を消さない。ライブはイベント経路が確定した後のみ有効。未観測時点から0を埋めない。DevModeで発生した事実を通常プレイと厳密に分離できないため、新統計はDev操作を含み得る旨を表示し、既存エンディングのみ既存設定でフィルターする。

### プロファイルの互換性

- `Profile.CurrentSchemaVersion=2`、`SaveReader.Version=4`（A）。Bはライブ保存のみでインポートに変更がなければ4のまま。Cの拡張コンポーネント取り込みで5。将来もファイル出力が変わる時だけ上げる。
- `ProfileStore.SchemaVersionOf` のスキーマ省略は明示的に1とする。JSONフィールドは既存と同じcamelCase。旧v1からは既存の観測、終了記録、除外、同定キー等をそのまま保持し、拡張は空。読み込んだだけで書き換えず最初の有効な変更時にv2を書く。v1の直前コピーを既存バックアップローテーションとは別に `profile.v1.json` として、ロック・元ファイルの同一性確認の下で1回保存する。バックアップに失敗すれば新スキーマの書き込みは保留。復旧でv1を読んだ場合も同じ保護を適用し、過去の保護コピーを上書きしない。
- v1でv2を読むと既存の新スキーマ保護により読取専用。v1へ継続ロールバックする場合は、v2を別名退避してv1のコピーを戻す。v2へ戻すときはファイルを戻す。両版の間で別々に更新した記録を自動マージしない。v2より新しい版も読取専用。既知スキーマ内の未知キー・未知拡張フィールドはJSON拡張データとして往復保持し、解釈/加算はしない。
- `ProfileSession` の単一状態・書き込み順序・外部更新検知・3世代バックアップを使う。同じ成功入力でv1記録と拡張観測を一度のロックで反映する。拡張失敗は既存の観測やゲームのセーブ結果へ伝播させない。

### 永続化の単位

v1の `ObservedValues` と枝刈りを拡張値の保存に流用しない。 `Profile.metricObservations` を別に持つ。v1が捨てた観測で拡張値が失われず、拡張の保持でv1のコロニー同定や選択順も変わらない。

| 項目 | 設計 |
|---|---|
| 観測キー | Aは解析したバイト列のSHA-256。XMLをEOFまで読むストリームで同時計算し、前後のサイズ/時刻が変化した入力は確定しない。コピー名/時刻は同値を増やさない。Bは成功保存ごとのGUID。Cは埋め込まれた checkpointId |
| コロニー照合 | v1で確定したコロニー集合にだけ追加する。正規 campaignId/別名一致 → 観測元のファイル名・サイズ・時刻の完全一致 → `CampaignMatcher.SameColony` による一意一致の順。完全一致でも識別根拠が食い違えば採用しない。複数/ゼロ候補は帰属不明。拡張のため新規コロニーを作らない。手動統合・除外後のv1集合を使用 |
| 観測共通 | source、schema/format、gameVersion、コロニー照合情報、saveTick、観測UTC、DLC情報、指標の要約。Aの同一ハッシュのUTCは、これまで正常解析したコピー群の最小ファイル時刻。新しいコピーを見ても押し上げない。観測元キーが複数なら一致判定ではそのいずれかを使う |
| 同じ入力の再解析 | 同じキー・同じ検証済み定義の良好値を優先。読み取り失敗や部分値が既知の良好値を消さない。指標定義の変更は registry revision で切り分け、異なる定義を合成しない。別内容の上書きは別観測 |
| 履歴 | 有効点の個数、合計、最初/最後、極値と最初のインデックス、計算済みの差分・閾値・連続要約のみ。生系列は解析の一時メモリに限る |
| Cの保存 | `GameComponent_RimworldStatistics` v2 に拡張ブロック `numericStatistics`。既存の campaignId / lineageEndings を継承。現在のチェックポイント、前回成功親、計測範囲、ファミリー別の累計と再開に必要な小さなアクティブ状態を保持 |
| Cのプロファイル | checkpointIdごとに親IDとtick/UTCを保持。完全一致再読は冪等、同じIDに異なるペイロードはそのチェックポイントを隔離。累計ペイロードは確認済みの子を持つ祖先から圧縮できる。初期実装では同値重複だけ削除し、移行時の保存削減を先走らない |

`metricObservations` の要約は分岐判定・代表値・観測極値・再解析・来歴が等価と証明できる場合だけ枝刈り可。取り込みは既存のファイルサイズ/時刻によるスキップを保ち、通常変更されていないファイルにはハッシュ目的で再アクセスしない。削除された元ファイルの未取得項目は不明。Bの値はプロファイルに記録し、Bより前のセーブやBのプロファイルを失った場合は復元不可。Cのイベントは記録済みセーブから取り込み直せる。

拡張観測のJSON名は `source, formatVersion, key, identity, fileAliases, gameVersion, saveTick, observedUtc, activeDlcIds, metrics`。 `identity` は既存 `ColonyIdentity`、`fileAliases` はAの `fileName/fileSize/lastWriteUtc` の組。 `metrics` はキーから値・内訳への辞書で、内訳キーなしのスカラーは予約キー空文字を使う。指標値は `coverage, integerValue, realValue, numerator, denominator, sinceTick, throughTick, sampleCount` のうち必要なフィールドのみ。率・平均は再計算できる分子と分母を必ず持ち、`sampleCount` が計算上の分母と同じ場合は省略できる。各キーの定義改訂番号は `revision` に保持し、異なる改訂番号の値は混ぜない。破損した個別の値は当該キーだけ隔離し、読み取り可能な同版未知フィールドは往復保持する。

Cのセーブ内JSONは `formatVersion=1, checkpointId, parentCheckpointId, saveTick, savedUtc, families`。 `families` は有効な取得単位名から `revision, sinceTick, throughTick, continuous, metrics, active` への辞書。 `active` は同じセーブで再開が必要なID・開始tick・最小の遷移状態のみ。イベントや操作の順序列は持たない。機能登録時の取得単位は台帳の節名に合わせる。旧版や未知機能の値を保持できるよう、読取はファミリーごとに分離する。

## 3. 数値集計と巻き戻し

### 過去観測の選び方

- 集計対象はv1で認識したコロニー。全体からは除外指定を引く。A、B、Cは別の取得範囲として各コロニーに代表観測を選ぶ。優先は有効 saveTick 降順 → UTC 降順 → 安定キー Ordinal 昇順。Aの同じ系列から得る値やBの同一スナップショットは同じ観測を使う。最新代表の欠損を同種の古い値で穴埋めしない。範囲が異なる数字を比で混ぜない。
- 既存資料の「最良記録」は台帳で観測横断としたA/Bの指標だけ、証拠として残る全観測から極値を取る。明示のないCの合計、比率、平均、極値は全て単一代表経路。ファイル数や全分岐の合計は一切使わない。
- 件数・量・完結期間の加算値は1コロニー1代表値の和。Max/Minは同じ種類の極値を取る。平均/率は同一単位の有効分子/分母の合算で再計算。日時・段階・ラベル・順位は合計しない。ユニーク件数は、人物/地点の個別値を「各コロニーでのユニーク数合計」と明示して合算する。品目最多などのラベル付き結果は代表個別値のみ。ただしランキングの定義で指定した横断順位は例外。順位同点は同順位、安定表示順はコロニーキー、内訳の同点はDefキーのOrdinal順。
- 既知値が一部の対象にしかない全体値は対象数と有効数を併記し部分記録とする。平均/率の分母は有効標本だけ。比較可能性が必要な順位は来歴・単位が等しい候補に限定し、完全と部分の順位表を混ぜない。比率や派生に必要な観測の時間範囲/集計範囲が異なれば不明。

### 履歴の境界

- 30000 tick/点の版・Defでのみ時間付き出力を作る。 `HistoryAutoRecorderGroup` に合わせた名目日を使い、点0は最初のゲームtick付近の観測。インデックスの時刻を実測到達tickとして扱わない。既知の対応表、`ticksGame>0`、点数 `floor(ticksGame/30000)+1`、先頭が有効、当該Def頻度の既知条件を「開始整合」とする。これはXMLからの整合判定であり、開始から無欠損を証明しない。履歴のラベルには「観測」を付ける。
- 1.5/1.6は匿名実セーブで間隔を裏づけるまで時間を使う出力を無効。未対応や整合しない系列は最大/最小/末尾と有効点の単純平均のみ可。平均は点数を母数とし、無記録期間へ外挿しない。欠測点は詰めず、区間と固定窓は欠測を跨がない。開始が必要な閾値は最初の成立まで全点有効である場合のみ。未達成と未記録は区別する。
- 15日=30点間隔、1ゲーム年=60日=120点間隔。連続日数は有効な隣接両端から積算。系列間の比は版・頻度・点数が一致し双方が開始整合、かつ各点と分母が有効な範囲のみ。最終額は代表系列の末尾点。先頭→末尾の純増には全点の有効性を要求せず両端を要求し、途中欠測は部分扱い。無効末尾を前の点で置き換えない。
- `Wealth_Total` 先頭floatのビット列をv1同定で従来どおり維持。拡張系列の壊れた値が既存同定に干渉しない。

### Cの確定プロトコル

1. `StartedNewGame` で初期ロスターを基準化し、必要なアダプターが準備済みなら新規起点。 `LoadedGame` はロードした `numericStatistics` の累計とアクティブ状態を復元し、埋め込まれた checkpointId を親候補とする。正常ロードした有効ブロックは、v1の登録・痕跡と同じProfileSession.Mutateで成功チェックポイントとして冪等に回収する。古い/削除済み/不明形式では新起点・途中計測。既知の値だけから未知期間を補間しない。初期セットアップ中は記録停止、ロード後にのみ受理。
2. イベントはゲームロジックのスレッドで即時にバッチ加算する。成功保存のみ永続化。 `SafeSaver.Save(string,string,Action,bool)` Prefixで documentElementName=`savegame` かつ現在のコンポーネントが一致する場合、呼出しごとにGUID、親、UTC、デタッチ済み集計スナップショットを仮作成。 `ExposeData` の Saving はその呼出しスコープだけをScribeで書く。 `SaveCompletedPatch` の既存Postfixで本体実行済み・拡張ブロック書込み完了・最終パス存在を確認し、親を更新し同じスナップショットをプロファイルに反映。ここでいう成功はSafeSaver本体が正常完了し本MODの確認を通ったこと。他MODの後続Postfix/Finalizerの成功を保証せず、後続パッチだけが例外を出しても確定済みの保存をロールバックしない。 `Finalizer` は例外をそのまま返してスコープのみ破棄。新規保存・オートセーブ・パーマデスは同じ入口で扱う。保存中の再入や非標準の別スレッドではその保存の拡張確定を抑止し、ゲーム側の処理は継続。
3. 保存完了前にエラーなら親を進めず、メモリのイベントは保持し次の成功保存で1回反映。v1の成功判定は変えない。 `SafeSaver` が置換後の `.old` 削除に失敗して例外を返す場合、Postfixを根拠に確定しない。後日、正常に読み取れる最終 `.rws` の埋め込みチェックポイントだけはインポート/ロードで回収できる。 既存の `.rws.old` は過去の正常チェックポイントの読取り対象のまま。未確定の `.rws.new` は対象外。
4. 成功したチェックポイントの累計は置換可能なスナップショット。コピー/反復ロードは同じID。祖先をロードした場合はその時点の累計を使い、旧子の値を上乗せしない。代表候補は成功チェックポイント全体を一意化した上で前述の順序。2子が同じ既知親を持つか、既知共通祖先から異なる枝へ達する場合「分岐あり」。親不明・MOD無効期間・矛盾・循環は「系譜不明」。ファイル時刻や同じtickだけで枝を推定しない。置換後例外のFを後日回収した場合、例外後にロードせず同じ親から正常保存したSとFは別保存枝と表示してよい。「分岐あり」は保存系譜の事実であり、巻き戻し操作の検出を意味しない。古い親を戻して未保存の間は通算を変えない。
5. 途中導入、機能の追加・無効化・フック失敗、DLC構成変更では出力ごとに `sinceTick/throughTick` と連続性を判定。確実に同じ定義・正常に連続した場合だけ完全。既存値を維持しつつ欠落以後は部分に落とす。区間を必要とする追跡は中断時に打ち切り。未来形式のコンポーネントを読み込んだら、読めるv1部分のみ使い、`numericStatistics` のScribe値は文字列1個（JSON、内部 `formatVersion`）として読み書きし、未知の内部形式は生文字列のまま引き継ぐ。解析できない内容から新規拡張を書かない。
6. 未セーブのライブ統計は全体に反映しない。v1の終了即時記録は継続。Dの終了時追加メタデータは同じ終了書き込みに含める場合に限りこの例外を共有。

## 4. 表示と負荷

- 「詳細統計」を独立タブで追加。既存の概要・エンディング・コロニー・取り込みは順と動作を維持。詳細の既定は「全コロニー」「すべてのカテゴリ」。切替は全体/個別、カテゴリ、日英表示名での絞り込み、名前/値並び替え。未知値は数値ソート末尾。検索と順序はセッション内のみ。
- 行は名称、数値・単位、出所・状態、対象/有効数。個別は範囲、個数、ゲーム内計測開始をツールチップ。内訳は必要時だけ展開。数字のみの一覧、グラフなし。DLC非対象は母数から除外。初めて出荷する条件付き指標はゲートを通過してから登録し、既存登録で保存根拠がない場合は `—`。
- `ProfileSession.GetView` は同期計算である。既存のダイアログによるバックグラウンド更新で、同じコロニー集合を使って数値ビューを生成。描画では immutable DTO を使用。検索/ソートは入力変更時のみ、スクロールで可視行だけ描画。描画から XML・JSON・ゲームDef探索を行わない。
- Aの読み込みは一度の `XmlReader` 走査。拡張の未知ノードはスキップ。上限は1系列262144点（復号後1 MiB）、1系列のBase64非空白文字2097152文字。上限超過は拡張系列だけ未記録、v1の読み取り経路を変更しない。差分・継続要約はO(N)。Bは成功セーブにつき収集1回、必要なゲームの既存リストを一巡し型別の走査を重ねない。部分取得は指標単位。
- C/Dのホットパスは成功遷移に1件、独立Harmonyクラス、対応版・DLCゲート、短いフィルター。生データ保存や毎tickの全マップ/Pawn/植物走査は不要。個人/Def/対象キーの辞書は1ファミリー1キー軸4096件を上限とする。上限後は既存キーと独立総数のみ続行し、種類数・順位・追跡期間等の依存値は部分または不明。無期限に増えるアクティブ追跡は不明終了時に解放。機能の無効化は1回の診断ログ。描画や毎イベントでファイルアクセスしない。
- 共通受け入れは、同じ版・データ・ハード・MOD順のv1との比較。試験手順と目標値は計画で固定し、基準に届かないファミリーだけ無効にして進める。
