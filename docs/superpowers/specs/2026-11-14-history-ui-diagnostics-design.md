# 履歴グラフの説明・取込失敗の診断・1日あたりの比較（設計）

作成日：2026-11-14
前提：[親子関係に基づく線の接続](2026-11-14-chart-history-lineage-design.md)（PR #258）、[次期開発候補調査 C4・C5](../../research/2026-11-14-next-development-opportunity-audit.md)、[追加調査 F02・F04](../../research/2026-11-14-additional-investigation-ja.md)

既存の検索・フィルタ・お気に入り・比較・ランキング・基本グラフ・CSV出力は変更しない。表示だけを追加し、保存値・集計・プロフィール形式は変えない。

## 1. 統計の最終記録とセーブ時刻の区別

チェックポイント系統グラフの最後の点より、このコロニーの最も進んだセーブ（セーブ観測とライブ記録の最大tick）が後にある場合、注記に「統計の最終記録は◯日、最も進んだセーブは◯日、それ以降の統計は記録されていない（別の分岐の場合もある）」と表示する（`MetricHistory.LatestSaveTick`）。最も進んだセーブが同じ分岐とは限らないため、線ではつながない。点ごとの「後のセーブにもそのまま含まれていた」はPR #258の `SavedTick`。

## 2. 記録元・確実性・欠測の説明

- 凡例（色見本つき）：記録値、一部のみの記録（Partial）、親子関係が未確認（白抜き）、値のない時点。該当するものだけを表示。
- 値のない時点：セーブ／チェックポイントはあるがこの統計の値がない点を、横軸に短い目印で示す。カーソルを合わせると「取得OFF、MOD・DLCが無効、旧形式など。0ではない」と説明する。ツールチップ領域は1つだけ使う（RimWorldは重なった領域を積み重ねて表示するため）。
- 注記に「記録 n点（一部のみ p点）、値のない時点 g点」。
- 重ねたコロニーの履歴が別の記録元（例：チェックポイントとセーブ時の値）の場合、従来は「履歴なし」と表示していたが、「記録元が異なるため重ねて表示できません」と正しく表示する。重ね描きはしない。

## 3. 取込失敗の診断（読み取り専用）

`ImportProblems.Classify` が、セーブの読込結果をプレイヤーが取れる対応ごとに分類する：読込中に変更（ゲームが保存中）、開けない（使用中・権限）、破損・不完全、RimWorldのセーブではない、コロニーを識別する情報がない、予期しないエラー。取込タブに原因別の件数と、失敗した読込は次回のスキャンで読み直すこと（`IsCurrentRead` は失敗を再読込する）を表示し、各行には従来どおり読込時の理由も残す。読込動作・保存内容は変更しない。外部へ送信する診断出力は追加しない（キャンペーンIDやMOD一覧を出さないため）。

## 4. 1日あたりの比較（期間正規化）

`MetricRates.PerDay` は次をすべて満たす値だけを、その値自身の記録期間（`ThroughTick − SinceTick`）の日数で割る。

- ライブ記録の加算できる合計（Source=Checkpoint、Overall=Sum、代表値、符号なし、単位は件数・シルバー・栄養）
- Coverage=Complete（ゲーム開始から欠けなく記録）。Partialは途中開始と記録の欠けを区別できないため対象外
- 記録期間が1日以上
- 「一度でも扱った種類の数」「訪れた別々のタイル数」「出産した別々の入植者数」「初めて20に達した組」のような**集合の大きさ**と、獲得・消費を合わせた名誉は対象外（時間に比例して増える量ではない）

コロニー比較の棒グラフと履歴グラフのツールチップに「1日あたり：x（記録期間 n日）」を追加。全コロニーの値は個別の比率を平均しない（表示しない）。

## 5. 検証

- `HistoryDiagnosticsTests`：1日あたりの対象・対象外（Partial／Unknown／短い期間／集合の大きさ／最大値・比率・状態・符号付き）、登録済み統計すべての対象が加算可能なライブ合計であること、取込失敗の分類と再読込の有無、`LatestSaveTick`。
- 実セーブ6件（読み取り専用）：チェックポイント系統グラフの `LatestSaveTick` が12,520,319、最後の点が12,348,927で注記の対象になる。これらのセーブのライブ統計は途中開始のPartialのため1日あたりは表示されない（正しい挙動）。読込失敗0件。
