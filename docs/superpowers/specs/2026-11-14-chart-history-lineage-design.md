# コロニー別統計履歴：セーブの親子関係に基づく線の接続（設計）

作成日：2026-11-14
関連：[Issue #72](https://github.com/pengin0503/Rimworld-Statistics/issues/72)、[次期開発候補調査 C1](../../research/2026-11-14-next-development-opportunity-audit.md)、[追加調査 §1](../../research/2026-11-14-additional-investigation-ja.md)、[グラフ設計（PR #255以前）](2026-11-14-metric-chart-drilldown-design.md)

## 1. 問題

PR #255 のコロニー別履歴グラフは、セーブ観測（`SaveFile`／`SaveSnapshot`／概要の基本値）を**同じ `ModCampaignId` なら前後の点を線で接続**していた。キャンペーンIDは「同じコロニー」の証拠であって、「同じセーブ分岐の連続した時点」の証拠ではない。巻き戻し・ロードし直し・兄弟分岐のセーブはすべて同じIDを持つため、ゲーム内日数順に並べると別の分岐の値を往復する線になり得る。

提供された6件の実セーブ（1.7.5005、読み取り専用）で現行mainを実行すると、親子関係の証拠がない 19:33→19:50 と、同じ古いチェックポイントを含むだけの 21:07→21:19 が線で接続されていた（設計上の誤りの実データ再現。ゲーム画面での目視確認ではない）。

## 2. 規則

線は「後の点のセーブが、前の点のセーブの子孫であることが証明できる」場合だけ引く。証明は埋め込みチェックポイントIDだけを使う（`CheckpointAncestry`）。

1. チェックポイントC自身のtickで保存されたセーブは、Cが記録した状態そのもの（**exact**）。
2. Cを含むがCより後のtickで保存されたセーブは、Cの**子孫**だが、C自身ではない。MODは新しい記録がない保存（全ファミリーOFF、読めないチェックポイントの保持、入れ子の保存）で最後のチェックポイントを変更せず書き戻すため（`CheckpointSaveSession`／`LiveMetricAccumulator.PrepareSave`）。このセーブを親として他の点を接続することはない。
3. チェックポイント同士は、一意・非衝突・同一キャンペーンで、子以前のtickを持つ親IDでだけ連鎖する。親欠落・衝突・循環・重複IDで連鎖は終わる。
4. 点Pは、Pの連鎖上で最も近い「exactな過去の点」に接続する。間に別分岐の点がある場合は `ContinuesFrom` で離れた点に接続し、隣の点（別分岐）とはつながない。
5. どの過去の点にも接続できない点は `Unlinked`（白抜き表示）。同じtickに別々のチェックポイントを持つセーブが混在する点（リロード後のオートセーブは同じtickに当たり得る）も、一つの状態とは見なさない。値が矛盾する場合は従来どおり欠測。
6. 欠測・Unknown・NotApplicable は値を持たない点のまま（ゼロにしない）。値のない点をまたいで線は引かない。
7. 同じtick・ファイル書込時刻・キャンペーンの組合せ、ファイル名、tick一致だけでは証明としない。ゲーム内のセーブ時スナップショットは、同じ保存で確定したチェックポイントIDを新たに `CheckpointKey` として記録し、以前の記録は取込済みセーブファイルの書込時刻とtickが完全一致する場合だけ対応付ける。

チェックポイント系統のグラフは従来どおり代表チェックポイントの親を辿る。追加で、同じチェックポイントがより後のtickのセーブにそのまま含まれていた場合、その最新のセーブtickを `SavedTick` として示す（「統計の取得時点」と「セーブ時点」の区別）。

## 3. 実セーブでの結果（匿名化）

ゲームtick順に A〜F（19:33、19:50、19:54、19:56、21:07、21:19）。

| 点 | 接続 | 理由 |
|---|---|---|
| A | 始点 | — |
| B | 白抜き | Bの親チェックポイントは提供ファイルにない |
| C | B | 直接の親 |
| D | C | 直接の親 |
| E | D | EのセーブはチェックポイントE′（tick 12,348,927、親はD）を含む子孫 |
| F | D（Eではない） | FもE′を含むだけで、Eの子孫である証拠はない |

チェックポイント系統グラフ：B・C・D・E′の4点。E′は1点のみ（E・F両方に含まれる同一チェックポイントを二重計上しない）で、`SavedTick` はFのtick。

元ファイルのSHA-256・サイズ・更新時刻は実行前後で一致。再現は `RWS_PRIVATE_SIX_SAVES_DIR` を設定して `PrivateSixSaveChartLineageAcceptanceTests` を実行する（CIではスキップ）。

## 4. 表示

- 線：証明された親子関係のみ。白抜きの点：前の記録との関係が確認できないセーブ（凡例を表示）。
- ツールチップ：未確認の関係、離れた点からの分岐、「この記録は◯日のセーブにもそのまま含まれていた」。
- 大量の点の間引き（`MetricHistoryPlot.Thin`）はCoreへ移し、欠測・白抜き・分岐元の点を必ず残して参照番号を付け替える。描画のみで保存値は変えない。

## 5. 互換性と性能

- プロフィール形式：`MetricObservation.CheckpointKey`（null時は書き出さない）を追加しただけ。旧版で開いた場合は拡張データとして保持され消えない（旧版はその記録を圧縮対象から外すだけ）。スキーマ番号・累積値・既存の集計は不変。
- 合成プロフィール（10件ごとに巻き戻し分岐、Release、7回の中央値、同一ローカル環境で各2回）でのグラフ構築：100セーブ 約0.4〜0.6ms→0.7〜0.9ms、3,000セーブ 約11ms→21〜27ms。グラフを開いたときの1回だけの処理（プロフィールのロック内）で、ゲーム中の保存処理は変わらない。

## 6. 未検証

- 実際のRimWorld画面での描画・ツールチップの目視確認。
- 既存プロフィールに残る `CheckpointKey` 導入前のセーブ時スナップショットは、対応するセーブファイルを取り込んでいない場合は白抜きで表示される（誤った接続より安全側）。
