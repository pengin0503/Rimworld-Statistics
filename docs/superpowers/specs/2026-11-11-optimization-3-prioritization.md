## 1. 判断基準

1. **誰が、いつ負荷を受けるか。** ゲームスレッド＞UIスレッド＞バックグラウンド。既定設定のユーザーに及ぶものを先にする。
2. **効果に根拠があるか。** 実測または試作で確かめたものを先にする。実ゲームでしか測れないものは、先に測る手順を用意し、書き換えは採用しない。
3. **意味を変えないか。** 統計ID、保存データ、集計結果、不明・部分・実験的の区別を変える案は採らない。
4. **小さく分けられるか。** 1タスクが1つのPRで完結し、単独で元に戻せること。

- `Checkpoint` かつ `compressed=True` の合計が 5MB 以上
- 同じ行の件数が 200 件以上

## 4. 依存関係と順序の理由

```
T0 ──┬─ T1 ─┐
     ├─ T2 ─┤
     ├─ T3 ─┼─ T7 ─┐
     ├─ T4 ─┤      ├─ T10 ── T11（着手条件付き）
     ├─ T5 ─┼─ T6 ─┤
     ├─ T8 ─┤      │
     └─ T9 ─┘──────┘
```

- **T0 が最初**：以降のすべての比較に使う。
- **T1〜T5 は互いに独立**。どの順でもよいが、表の順（小さく確実なものから）を勧める。
- **T6 は T5 の後**：どちらも `ModProviderAdapters.cs` を触る。
- **T7 は T3 の後**：T3 が `ImportEngine` の再読取条件を1箇所に寄せ、T7 がそれを使う。
- **T10 は T1〜T9 の後**：ファイルを分割すると、それ以前に書かれた差分が当てにくくなる。分割は最後にまとめて行う。
- **T11 は T10 の後**：分割後の `ProfileMutations.Checkpoints.cs` に手を入れる。

## 5. リスク評価

| タスク | 起こり得る失敗 | 抑え方 |
|---|---|---|
| T1 | フィールド変更後に古いハッシュを返す | 記憶するのは「5フィールドの値と結果の組」。呼び出しのたびに現在値と照合するので、無効化の通知に頼らない。各フィールドを変えるテストを置く。 |
| T2 | 結合結果が変わる | 旧実装をテスト内に写し、長さ3までの全組み合わせで一致を確かめる。 |
| T3 | 寄せた先で条件が微妙に変わる | 式をそのまま移す。既存テストが変更なしで通ること。 |
| T4 | 記録する箇所まで置き換えて回数が減る／別スレッドの欠測印が付かなくなる | 置換するのは「戻り値をnullと比べるだけ」の箇所に限る。欠測印の処理は確認側にも残す。置換後の検索で残数を確かめる。 |
| T5 | 登録が確定する前に一覧を固めてしまう | 既存の `Lazy` と同じ時点で初めて作る。固める時点は変えない。 |
| T6 | フックの付け忘れで取得できなくなる／旧アドオン併用時に二重に付く | 「登録は従来どおり、パッチ適用だけを遅らせる」。失敗時は単位を閉じる既存の経路に乗せる。旧アドオンの判定は従来の位置のまま。実ゲームで ON 1件・OFF 0件を確認する。 |
| T7 | 読取中にファイルが変わり古い結果を採用する／中断が遅れる／順序が変わり結果が変わる | 反映は必ずファイル名順。先読み結果は、反映時点のサイズ・更新時刻と一致したときだけ使う。順次実行と並列実行でプロファイルが一致するテストを置く。 |
| T8 | 除外操作や並べ替えが表示に反映されない | 保持の鍵は「ビューの参照・列・昇降」。除外すると新しいビューになるので作り直される。手動確認項目を追加する。 |
| T9 | 行を作り直した後に古いツールチップが出る | ツールチップの識別番号に作り直しの通番を混ぜる。 |
| T10 | 移動のつもりで内容が変わる | メソッド本体は1文字も変えない。テストと、実セーブ取込後プロファイルのSHA-256が分割前後で一致すること。 |
| T11 | 退避した値を読めず統計が欠ける／退避と本体の不整合 | 退避ファイルへの追記と同期が終わってから本体を軽くする。読めない場合は不明として扱い、ゼロにしない。圧縮済み祖先を参照する3経路（競合時の復元、最後に取得できた値、観測横断の最大・最小）が退避前と同じ結果になるテストを置く。 |
