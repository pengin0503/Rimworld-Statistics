## プロンプト

```text
あなたは pengin0503/Rimworld-Statistics（RimWorld 1.7 用MOD、C# / .NET 10）の実装担当です。
作業パッケージ {{PKG}}（Issue #{{ISSUE}}）を実装し、テストし、PRを作ってください。リリースと Steam Workshop の更新はしません。

# 最初に読むもの（この順で）

1. docs/superpowers/plans/2026-11-12-feature-expansion-plan.md
   「Global Constraints」「Review Focus」「準備」「共通の完了確認」と、{{PKG}} の節（M のときは「M1〜M7 の共通タスク」と表の該当行も）。
2. docs/superpowers/specs/2026-11-12-feature-expansion-design.md
   §0（この設計の扱い）、§2（不変条件）、§5 のうち {{PKG}} が使う共通基盤、§6 の該当節。
3. M のときだけ：docs/superpowers/specs/2026-11-12-feature-expansion-mod-statistics.md の §1、§3 の該当節、§4。
4. Issue #{{ISSUE}} と、そのコメント（前のパッケージで決まったことが書かれていることがある）。

古い計画書・調査資料（docs/research、docs/superpowers の 2026-11-11 以前のファイル）は、上の資料が名指ししたものだけ読めば足ります。最初から調査をやり直さないでください。

# 設計の扱い

- 不変条件（設計 §2）と、受入条件が表す意図は変えない。
- クラス名・メソッド名・ファイルの置き場所・UIの細部は推奨です。より簡単で確実な方法があれば変えてよい。変えたら PR 本文の「設計から変えた点」に理由を1〜3行で書き、必要なら設計書の該当節も同じPRで直す。
- 前のパッケージが作った型・メソッド（計画の Interfaces）を使う。名前が計画と違っていたら、実際のコードに合わせる。

# 手順

1. 最新の main から、ブランチ `feat/{{PKG}}-<短い説明>`（M のときは `mod/{{PKG}}-<短い説明>`）を作る。
2. 計画の「準備」を実行し、基準のビルドとテストが通ることを確かめる。通らなければ何も変更せずに止まり、出力を報告する。
3. {{PKG}} の Task を上から順に行う。Core のテストは先に書き、失敗することを確かめてから実装する。
4. M のときは、Step 1（対象の版の固定と「確認が必要」な点の確認）を最初に行う。確かめられない点があれば、その統計は作らずに Issue に理由を書く。M5 は、所有者が 1.7 の DLL を用意していなければ着手せず、その旨を Issue に書いて止まる。
5. 計画の「共通の完了確認」をすべて行う。
6. docs/manual-test-checklist.md に、このパッケージの手動確認項目を追記する。
7. コミットして push し、PR を作る。PR 本文は次の見出しで書く：
   - 概要
   - 自動で確かめたこと（コマンドと結果。テスト件数、失敗0）
   - 手動確認が必要なこと（docs/manual-test-checklist.md の追記箇所）
   - 設計から変えた点（なければ「なし」）
   - 関連 Issue（Closes #{{ISSUE}}。他MODで実ゲーム確認が残るときは Closes にせず Refs にする）
8. CI（numeric-verification.yml）の結果を確認し、失敗したら原因を直す。テストを無効化・削除して通さない。

# 守ること

- 統計ID・改訂番号・SaveReader.Version・プロフィールのスキーマ・チェックポイント形式を変えない。既存テストの期待値を書き換えない。
- 欠測を0にしない。Partial／Experimental を昇格させない。
- 範囲外のコロニーをコロニー一覧から取り除かない（観測の帰属が変わる）。
- お気に入り・グループを profile.json に保存しない。
- 実験的取得は既定OFF。OFF・対象MODなしでパッチ0件。毎tickの処理を足さない。
- R2 は読み取りのみ。環境変数の値を表示・保存・コミットしない。私有のセーブ・MOD一覧・ゲームDLLをコミットしない。
- RWMT（pengin0503/RimWorld-for-mod-test）での実ゲーム検証が必要なときは、RWMT 側の PR を作るところまでにし、マージと実行は所有者の指示を待つ。
- 実ゲームで確かめていないことを「確認済み」と書かない。

# 最後に報告すること

- 作ったPRのURL、変更の要約、テスト件数と結果
- 手動確認が必要な項目
- 設計から変えた点と、次のパッケージへの申し送り（Issue #{{ISSUE}} にもコメントで残す）
```
