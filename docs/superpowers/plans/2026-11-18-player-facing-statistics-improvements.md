# 通算統計のプレイヤー向け改善 実装計画

**状態**　採用済み・実装待ち。対象は Rimworld Statistics の RimWorld 1.7 対応版。

**目的**　プレイ中に統計を確認し、過去のコロニーや出来事を探し、よく見る履歴を少ない操作で開けるようにする。

**構成**　既存の統計・年表・履歴モデルを再利用する。表示名とお気に入りだけを既存の `ViewPreferences` に保存し、拡大範囲と年表フィルターは画面内の状態として扱う。C# / Verse IMGUI / .NET 10 / 既存の12言語 Keyed XML を使用する。

## 並行作業

| 担当 | 採用機能 | 主な担当ファイル |
| --- | --- | --- |
| A | プレイ中の統計アクセス | `MainMenuButtonPatch.cs` とゲーム中の起動処理 |
| B | コロニー表示名・検索、コロニー別グラフのお気に入り | `ViewPreferences.cs`、`Dialog_RimworldStatistics.cs` の表示設定、`ColoniesTab.cs`、`OverviewTab.cs` |
| C | 履歴グラフの期間拡大 | `Dialog_ColonyMetricHistory.cs` と表示範囲の計算 |
| D | 年表の研究名・出来事・ゲーム内日数での絞り込み | `Dialog_ColonyChronicle.cs` と絞り込み処理 |

A・B・C・Dは別ブランチ・別PR。AとDは先に着手できる。BとCも独立した処理・テストから同時に着手できるが、Bの `ColoniesTab.cs`、Cの `Dialog_ColonyMetricHistory.cs`、Bのウィンドウ配線が #358 と重なる場合は、該当箇所の最終統合を #358 の取り込み後に行う。AとBがウィンドウの共通部分を変更する場合は、既存の総括ダイアログを直接使えるか確認し、共有入口の変更は一方に寄せる。翻訳は担当ごとの Keyed XML を使う。README等の横断更新は統合時にまとめる。

## 共通条件

- 最新 `main`、既存PR、#357・#358 の差分を着手時に確認する。Gemini担当のIssueの修正は取り込まない。
- 統計キー、集計ルール、ゲームイベントの記録、セーブ形式、プロフィール本体のスキーマを維持する。欠測を0に置き換えず、未確認の分岐を連結しない。R2と元セーブは読み取り専用。
- ゲームAPIの確認は [現行仕様と旧仕様の区別](../README-current-and-historical.md) と [R2参照台帳](../../research/2026-11-10-r2-private-reference-inventory.md) から始める。必要なAPIだけ確認する。
- 既存テストを活用し、各担当の境界条件を対象に回帰テストを追加する。CIと同じ `dotnet build tools/ci.slnx -c Release -m -p:UseNuGetRefs=true`、`dotnet test --project Tests/RimworldStatistics.Core.Tests/RimworldStatistics.Core.Tests.csproj -c Release --no-build`、`bash tools/check_keys.sh` を実行する。

## A プレイ中の統計アクセス

- [ ] ゲーム中のメニューまたは任意のキー設定から「通算統計」を開けるようにする。既存のタイトル画面ボタンを維持し、ゲーム中入口から自動セーブ取り込みを開始しない。既定のキーを割り当てる場合は既存操作との衝突を確認する。
- [ ] 現在の `GameComponent_RimworldStatistics` が持つキャンペーンIDを、既存のコロニー識別で解決し、総括を開く。表示のためにIDを生成したり、名前で別コロニーを推定したりしない。まだ対応する保存済み記録がない場合はその旨を示し、通常の通算統計を開けるようにする。
- [ ] 保存済み統計であることと最終記録時点を表示する。同名コロニー、初回保存前、タイトル画面復帰、別セーブへの切替を確認する。ゲームAPIはメインスレッド上で使い、集計は既存の非同期経路を利用する。

## B 表示名・検索とコロニー別グラフのお気に入り

- [ ] コロニー一覧で表示名を設定・解除できるようにし、表示名、元の派閥名、ワールド名から検索できるようにする。表示名を一覧やコロニー選択欄で使い、セーブ内の派閥名や識別キーは変更しない。
- [ ] コロニーキーと統計キーの組を登録・解除できるようにし、概要のお気に入りから対象の折れ線グラフを直接開けるようにする。従来の統計単位のお気に入りを維持する。登録操作を履歴画面に置く必要がある場合はCと担当を合わせ、同じ描画箇所を同時に編集しない。
- [ ] 既存の設定保存・復元経路を使い、旧設定、重複登録、同名コロニー、統合による旧キー、未導入MODなどで開けなくなった対象を確認する。利用不能な登録は利用者が解除できるようにする。

## C 履歴グラフの期間拡大

- [ ] 折れ線グラフで開始日・終了日を選び、指定期間の表示と全期間への復帰をできるようにする。既存の2点間比較と拡大操作を区別する。
- [ ] 拡大時は主系列と重ね合わせ系列に同じX軸を適用し、目盛りとツールチップも表示範囲に合わせる。範囲外の点は比較用の選択候補にせず、拡大によって元の履歴や連続性の判定を変更しない。
- [ ] 逆順・同日・空の範囲、欠測を挟む範囲、重ね合わせの観測日が異なる範囲、全期間への復帰を確認する。

## D 年表の研究名・出来事・ゲーム内日数での絞り込み

- [ ] 年表に文字検索と開始日・終了日の任意指定を追加する。翻訳済み研究名、出来事名、区間内の統計名を検索対象にする。種別フィルター、並び順、選択中の分岐と併用できるようにする。
- [ ] 単日の記録は指定範囲に含まれる場合に表示し、区間記録は範囲と重なる場合に元の区間表記のまま表示する。発生日不明の痕跡は日数指定時に除外し、テキストのみの検索では名前で探せるようにする。
- [ ] 範囲の両端、片側だけの指定、不正値と逆順、空入力、未導入MODの研究名、分岐切替、結果なし・解除を確認する。検索入力でセーブの再読み込みや年表モデルの再構築を行わない。

- **A**　プレイ中に現在のコロニー総括を開けるようにしてください。保存済み記録の時点と、記録がまだない場合の表示も実装してください。
- **B**　コロニー表示名と検索、コロニー×統計の履歴グラフのお気に入りを実装してください。旧表示設定との互換性を維持してください。
- **C**　コロニー履歴の期間拡大と全期間への復帰を実装してください。比較、重ね合わせ、欠測表示を維持してください。
- **D**　年表に研究名・出来事・ゲーム内日数の絞り込みを実装してください。分岐、区間表記、発生日不明の扱いを維持してください。
